== Goals

=== [[G-01]]G-01 Produce Sparring responses and hold every rule that governs them

The element shall be the sole location of generation, moderation, rate limiting, and session policy, so that no rule is editable from a device the project does not control. +
_Success criteria (qualitative):_ No client contains a provider credential or any limit the element does not independently enforce. +
_Satisfies:_ xref:L2-system-design-concept.adoc#SG-01[SG-01 Start a session from a personal device with no], xref:L2-system-design-concept.adoc#SG-04[SG-04 Run unattended and absorb misuse without operator]

=== [[G-02]]G-02 Keep a session usable across interruption

The element shall resolve a session identifier to its full state and history for as long as the session is live. +
_Success criteria (qualitative):_ A session fetched after an interruption returns identical content to what its participant last saw. +
_Satisfies:_ xref:L2-system-design-concept.adoc#SG-03[SG-03 Survive interruption of the visitor's session]

=== [[G-03]]G-03 Persist every interaction with its origin fixed at creation

The element shall record sessions and exchanges tagged pilot or live at the moment of creation, with no later assignment or correction. +
_Success criteria (qualitative):_ Exhibition material is extractable by filtering one stored value. +
_Satisfies:_ xref:L2-system-design-concept.adoc#SG-05[SG-05 Record every interaction with its origin fixed at]

=== [[G-04]]G-04 Decide what may be stored, and let the visitor's own choice decide what may be projected

The element shall assess each contribution for suitability before it is stored, rejecting an unsuitable one so the visitor can edit and resubmit rather than silently hiding it after the fact. Whether a _stored_ exchange is projected is then a separate question, answered by the visitor's own projection consent, not by re-running suitability at display time. +
_Success criteria (qualitative):_ Nothing unsuitable is ever stored. A session that declined projection consent never appears on the wall regardless of content; a session that granted it does, for as long as its content keeps passing the write-time check. +
_Satisfies:_ xref:L2-system-design-concept.adoc#SG-07[SG-07 Gate public projection at the moment of submission]

=== [[G-05]]G-05 Keep the display surface populated

The element shall supply display material at all times, falling back to pilot-origin sessions when insufficient live material is eligible. +
_Success criteria (qualitative):_ The display feed is never empty while the element is running and pilot material exists. +
_Satisfies:_ xref:L2-system-design-concept.adoc#SG-06[SG-06 Never present an empty surface]

=== [[G-06]]G-06 Absorb load and misuse without failing

The element shall reject excess requests, over-length contributions, and over-long sessions as expected conditions, and shall continue serving other visitors when it does. +
_Success criteria (qualitative):_ A rejected request affects only its own session. +
_Satisfies:_ xref:L2-system-design-concept.adoc#SG-04[SG-04 Run unattended and absorb misuse without operator]

=== [[G-07]]G-07 Capture optional session feedback without gating anything

The element shall record whatever rating and open-feedback a visitor submits at session end, and shall accept a partial or empty submission the same as a complete one. +
_Success criteria (qualitative):_ A submission carrying no answers at all is accepted and simply stored as nothing to record, not rejected. +
_Satisfies:_ xref:L2-system-design-concept.adoc#SG-09[SG-09 Collect an optional visitor self-report at session]

'''

== Use cases

Use cases at this level are thin, because most of this element's behaviour is reached through technical interfaces rather than as user-facing functionality. The one exception is the operator path, which is a genuine use case with a human actor.

=== [[UC-01]]UC-01 The operator seeds pilot material

_Actors:_ xref:L2-system-design-concept.adoc#UT-03[UT-03 Operator] +
_Prerequisites:_ Pilot transcripts exist in the expected structured form. +
_Achieves:_ <<G-03,G-03 Persist every interaction with its origin fixed at>>, <<G-05,G-05 Keep the display surface populated>> +
_Realises:_ SSc-03

- *[[ST-01-1]]ST-01-1* _(Activity)_ xref:L2-system-design-concept.adoc#UT-03[UT-03 Operator] places a transcript file where the element can read it and invokes the import path (<<TI-05,TI-05 Import pilot material>>).
- *[[ST-01-2]]ST-01-2* _(Function-call)_ The element calls <<TF-06,TF-06 Import pilot transcripts>> with the file contents. <<TF-06,TF-06 Import pilot transcripts>> validates each transcript, creates its session and exchanges with origin fixed as pilot, and returns a per-transcript outcome.
- *[[ST-01-3]]ST-01-3* _(Activity)_ The element reports how many transcripts were imported and names any that were rejected.

*Alternative scenarios*

- *[[EX-01-1]]EX-01-1* _(extends <<ST-01-2,ST-01-2>>)_ One or more transcripts are malformed. Those are rejected and named; the remainder are imported. The import does not abort. _Outcome:_ Alternative-success.

NOTE: This path performs no generation and never calls xref:L2-system-design-concept.adoc#PE-01[PE-01 Language generation API]. The Sparring responses already exist in the transcripts, and regenerating them would produce material that no pilot session actually contained.

'''

== User interfaces

Not applicable. This element presents no user interface. xref:L2-system-design-concept.adoc#UT-03[UT-03 Operator] reaches it through <<TI-05,TI-05 Import pilot material>>, which is a technical interface invoked directly on the host rather than a surface.

'''

== Technical functions

=== [[TF-01]]TF-01 Process a visitor turn

_Detail level:_ Stepwise +
_Achieves:_ <<G-01,G-01 Produce Sparring responses and hold every rule that>>, <<G-04,G-04 Decide what may be stored, and let the visitor's own>>, <<G-06,G-06 Absorb load and misuse without failing>>

The element's central function. Everything that happens between a visitor pressing submit and a response returning is here, which is what keeps retry and error handling in one place rather than scattered across interfaces.

Visual companion to the steps below — the gate order and its five
cheap-reject branches, cheapest checks first. The step list is the
authoritative source.

[source,mermaid]
----
flowchart TD
  start(["Visitor submits a turn"]) --> rl{"Rate limit reached?"}
  rl -- yes --> stopRate["Return: limit reached — FS-01-1"]
  rl -- no --> sess{"Session known, not expired?"}
  sess -- no --> stopSess["Return: session unknown — FS-01-2"]
  sess -- yes --> turn{"Turn allowance exhausted?"}
  turn -- yes --> stopTurn["Return: turn limit — FS-01-3"]
  turn -- no --> len{"Empty or over-length?"}
  len -- yes --> stopLen["Return: rejected — FS-01-4"]
  len -- no --> mod{"Suitable for projection? — TF-02"}
  mod -- no --> stopMod["Return: content-flagged<br/>FA-01-2, resume — visitor edits and resubmits"]
  mod -- yes --> gen["Request response from PE-01 — FS-01-7/8, TO-01"]
  gen --> ok{"Response received?"}
  ok -- no, exhausted retries --> stopGen["Return: generation-failed<br/>FA-01-1, terminate"]
  ok -- yes --> persist["Write exchange, increment turnCount,<br/>derive scenario on first turn — FS-01-9…11"]
  persist --> done(["Return response + remaining allowance"])
----

NOTE: Every `stop*` box writes nothing to <<E-01,E-01 Session>> or
<<E-02,E-02 Exchange>> — only the persist step does. The first four gates
(rate limit, session, turn count, length) never reach a provider call;
suitability is the last cheap check before one is made.

- *[[FS-01-1]]FS-01-1* _(Function-call)_ Call <<TF-03,TF-03 Enforce request limits>> with the request origin. If it reports the limit reached, return that condition and stop.
- *[[FS-01-2]]FS-01-2* _(Entity-access)_ Read the session from <<E-01,E-01 Session>> by its identifier (<<E-01.1,E-01.1 sessionId>>). If absent or expired, return a session-unknown condition and stop.
- *[[FS-01-3]]FS-01-3* _(Data-operation)_ Compare <<E-01.8,E-01.8 turnCount>> (turnCount) against the session's effective turn allowance — the base `TURN_ALLOWANCE` plus <<E-01.13,E-01.13 bonusTurns>> (bonusTurns), which <<TF-09,TF-09 Extend a session's turn allowance>> raises. If the allowance is exhausted, return a turn-limit condition and stop.
- *[[FS-01-4]]FS-01-4* _(Data-operation)_ Trim the contribution and check it against the length bound. If it is empty or over-length, return a rejected condition and stop. A curated opening prompt (`OPENING_PROMPTS`, config.php — matched exactly against the whitelist, not by prefix, so a visitor cannot bypass the bound by imitating it) is exempt from the length check, since it is vetted copy rather than visitor-typed text. No provider call has been made at this point, which matters because this is the cheapest rejection path and the one most likely to fire.
- *[[FS-01-5]]FS-01-5* _(Function-call)_ Call <<TF-02,TF-02 Assess a contribution for projection suitability>> with the contribution. <<TF-02,TF-02 Assess a contribution for projection suitability>> returns a suitability outcome.
- *[[FS-01-6]]FS-01-6* _(Data-operation)_ If <<TF-02,TF-02 Assess a contribution for projection suitability>> reported the contribution unsuitable, return a content-flagged condition and stop. Nothing is written to <<E-01,E-01 Session>> or <<E-02,E-02 Exchange>>, and no provider call for a response is made — this is the same cheap-rejection reasoning as <<FS-01-4,FS-01-4>>, just one check later. The session itself is not altered; only this turn is rejected.
- *[[FS-01-7]]FS-01-7* _(Entity-access)_ Read the session's prior exchanges from <<E-02,E-02 Exchange>> (<<E-02.3,E-02.3 visitorContribution>>, <<E-02.4,E-02.4 sparringResponse>>) in order, to supply conversational context.
- *[[FS-01-8]]FS-01-8* _(Outbound-call)_ Call <<TO-01,TO-01 Request a Sparring response>> with the system prompt (xref:L2-system-design-concept.adoc#SE-04[SE-04 System prompt]), the prior exchanges, and the new contribution. Expect a response text. _Call behaviour:_ Synchronous. Timeout is 20 seconds (`GENERATION_TIMEOUT_SECONDS`, config.php — xref:L2-system-design-concept.adoc#SQR-01[SQR-01 A Sparring response arrives, or its absence is visible]). Two attempts, with a short delay between them, on transport failure, timeout, or a provider 5xx. *No retry on a provider rate-limit or quota response*, because retrying a rate limit deepens it; return a generation-failed condition immediately. *No retry on a content-policy refusal from the provider*, which is a determinate outcome rather than a transient fault. On exhausted attempts, return a generation-failed condition. Nothing is written to <<E-02,E-02 Exchange>> on any failure path, so a failed turn leaves no partial exchange in the record.
- *[[FS-01-9]]FS-01-9* _(Entity-access)_ Write a new exchange to <<E-02,E-02 Exchange>> carrying the contribution (<<E-02.3,E-02.3 visitorContribution>>), the response (<<E-02.4,E-02.4 sparringResponse>>), the session reference (<<E-02.2,E-02.2 sessionId>>), and its position (<<E-02.5,E-02.5 position>>).
- *[[FS-01-10]]FS-01-10* _(Entity-access)_ Increment <<E-01.8,E-01.8 turnCount>> (turnCount) and update <<E-01.9,E-01.9 lastActiveAt>> (lastActiveAt).
- *[[FS-01-11]]FS-01-11* _(Function-call)_ If this was the session's first exchange, call <<TF-05,TF-05 Derive a scenario statement>> to derive the scenario statement and write it to <<E-01.5,E-01.5 scenario>>.
- *[[FS-01-12]]FS-01-12* _(Data-operation)_ Return the response, the remaining turn allowance, and the session state.

*Alternative flows*

- *[[FA-01-1]]FA-01-1* _(extends <<FS-01-8,FS-01-8>>)_ Provider rate limit, quota exhaustion, timeout, transport failure after retries, or content-policy refusal. All return a generation-failed condition to the caller and write nothing. Grouping is deliberate: the calling client takes the same action for every one of these, and distinguishing them would produce a taxonomy nobody acts on. The distinction is preserved in logs rather than in the response. _Outcome:_ Terminate.
- *[[FA-01-2]]FA-01-2* _(extends <<FS-01-6,FS-01-6>>)_ The contribution is unsuitable. Unlike <<FA-01-1,FA-01-1>>, this is not terminal — the caller (xref:L2-system-design-concept.adoc#SE-01[SE-01 Input client]) tells the visitor to edit and resubmit, and the input field re-enables with the text preserved. _Outcome:_ Resume.

=== [[TF-02]]TF-02 Assess a contribution for projection suitability

_Detail level:_ Stepwise +
_Achieves:_ <<G-04,G-04 Decide what may be stored, and let the visitor's own>>

Determines whether a contribution may be stored and answered at all — and, because only stored content can ever be projected (<<G-04,G-04 Decide what may be stored, and let the visitor's own>>), this is also what keeps unsuitable material off the public surface. It determines whether _this turn_ proceeds, not whether the visitor's session does: on an unsuitable result the visitor edits and resubmits, they are not cut off.

- *[[FS-02-1]]FS-02-1* _(Data-operation)_ Check the contribution against a maintained term list covering profanity. A match returns unsuitable without a provider call.
- *[[FS-02-2]]FS-02-2* _(Outbound-call)_ Call <<TO-02,TO-02 Request a classification>> with the contribution and a classification instruction. Expect one of: suitable, contains-personal-information, targets-real-person. _Call behaviour:_ Synchronous, short timeout, single attempt, no retry. *On any failure, return unsuitable.* Failing closed is correct here: the cost of not projecting a suitable contribution is that one item is missing from a wall, and the cost of projecting an unsuitable one is unrecoverable once it is six feet tall in a public room.
- *[[FS-02-3]]FS-02-3* _(Data-operation)_ Map the classification to an outcome and return it.

IMPORTANT: The distinction this function must get right (xref:L2-system-design-concept.adoc#AP-07[AP-07 Attempts to argue the Sparring partner out of its]): _Targets-real-person_ means the harmful content — hate speech, harassment, threats, sexual content — is aimed at or about a real, identifiable person or group. It does *not* mean a visitor who is hostile toward, arguing with, pressuring, or instructing the Sparring partner to abandon its position, however extreme the tone — the Sparring partner is software, not a person, and that visitor is engaged with the exercise; their attempt is the observation the installation exists to produce. The classification instruction must state this distinction explicitly rather than leaving it to the model's default reading of "unsafe language", because hostility-at-the-AI and harm-at-a-person can otherwise look similar and only one should be withheld.

IMPORTANT: A second distinction the instruction must also get right, found in testing: stating the xref:L2-system-design-concept.adoc#AP-07[AP-07 Attempts to argue the Sparring partner out of its] distinction was not enough on its own — without also stating what the exercise's subject matter actually _is_, the classifier had nothing to check arguing-the-exercise against, which produced misclassifications in the other direction. Both the topic itself and the target-based carve-out need to be explicit in the instruction — omitting either produces a failure mode this requirement exists to prevent, from a different direction.

_Contains-personal-information_ covers names, contact details, and health, financial, or comparably personal circumstances. This case is expected to arise most often in exactly the situation xref:L2-system-design-concept.adoc#AP-07[AP-07 Attempts to argue the Sparring partner out of its] protects: a visitor under real pressure disclosing something real while trying to get the system to relent. That turn is rejected and not stored; the visitor edits it and continues — the session is not ended over it.

=== [[TF-03]]TF-03 Enforce request limits

_Detail level:_ Narrative +
_Achieves:_ <<G-06,G-06 Absorb load and misuse without failing>>

Reads the current window for the request origin from <<E-03,E-03 Rate limit window>>, increments it, and reports whether the allowance is exceeded. Windows are keyed on a hashed origin (<<E-03.1,E-03.1 originHash>>), so no raw address is stored. Expired windows are reset in place rather than swept by a separate process, which avoids a scheduled job on an unattended host. Threshold is 10 requests per 60-second window (`RATE_LIMIT_MAX_REQUESTS`, `RATE_LIMIT_WINDOW_SECONDS`, config.php), set below the provider's own limits per xref:L2-system-design-concept.adoc#SC-04[SC-04 Generation is rate-limited and metered by the provider]. No goal relation beyond <<G-06,G-06 Absorb load and misuse without failing>>: this is a guard, not business logic.

=== [[TF-04]]TF-04 Assemble display material

_Detail level:_ Stepwise +
_Achieves:_ <<G-05,G-05 Keep the display surface populated>>, <<G-04,G-04 Decide what may be stored, and let the visitor's own>>

Produces the ordered items the projection renders. Every decision about what appears on the wall is made here, so that xref:L2-system-design-concept.adoc#SE-02[SE-02 Display client] carries no policy (xref:L3-SE-02-display-client.adoc#C-02[C-02 This element holds no selection or ordering policy] of that element).

- *[[FS-04-1]]FS-04-1* _(Entity-access)_ Read live-origin sessions from <<E-01,E-01 Session>> where <<E-01.6,E-01.6 displayable>> (displayable) is true and at least one exchange exists, ordered by <<E-01.9,E-01.9 lastActiveAt>> (lastActiveAt) descending, up to the item limit. The item limit is passed in by the caller (<<TI-04,TI-04 Retrieve display material>>, resolved from the requesting display profile; a default applies when none is given) — this function does not read it from configuration itself.
- *[[FS-04-2]]FS-04-2* _(Data-operation)_ If fewer items were found than the limit, continue at <<FS-04-3,FS-04-3>>. Otherwise continue at <<FS-04-4,FS-04-4>>.
- *[[FS-04-3]]FS-04-3* _(Entity-access)_ Read pilot-origin sessions from <<E-01,E-01 Session>> under the same eligibility conditions, ordered by <<E-01.9,E-01.9 lastActiveAt>> descending, and append until the limit is reached.
- *[[FS-04-4]]FS-04-4* _(Entity-access)_ For each selected session, read its most recent exchange from <<E-02,E-02 Exchange>> (<<E-02.3,E-02.3 visitorContribution>>, <<E-02.4,E-02.4 sparringResponse>>). Which exchange to select was an open decision (xref:L2-system-design-concept.adoc#SE-02[SE-02 Display client] xref:L3-SE-02-display-client.adoc#TBC-04[TBC-04 Which exchange pair per session.], resolved), made here; changing it would not affect xref:L2-system-design-concept.adoc#SE-02[SE-02 Display client].
- *[[FS-04-5]]FS-04-5* _(Data-operation)_ Build each item from the session's scenario (<<E-01.5,E-01.5 scenario>>), its refined title if one exists yet (<<E-01.12,E-01.12 title>>; `null` otherwise — <<TF-07,TF-07 Refine a session title>> runs asynchronously, so this item is not blocked on it), the exchange pair, the origin (<<E-01.4,E-01.4 origin>>), and a recency position. Return the ordered list.

=== [[TF-05]]TF-05 Derive a scenario statement

_Detail level:_ Narrative +
_Achieves:_ <<G-05,G-05 Keep the display surface populated>>

Produces the short context line shown above an exchange, from the session's first visitor contribution. The initial approach is to trim that contribution to a bounded length, which costs nothing. If opening contributions prove to read badly as context lines when checked against pilot transcripts, the fallback is a single generation call via <<TO-02,TO-02 Request a classification>>, with the result written once to <<E-01.5,E-01.5 scenario>> and never recomputed. Computing it per render would multiply provider cost by the polling rate, which is the specific mistake this note exists to prevent.

=== [[TF-06]]TF-06 Import pilot transcripts

_Detail level:_ Stepwise +
_Achieves:_ <<G-03,G-03 Persist every interaction with its origin fixed at>>, <<G-05,G-05 Keep the display surface populated>>

- *[[FS-06-1]]FS-06-1* _(Data-operation)_ Parse the supplied file and validate each transcript's structure. Collect malformed ones for reporting rather than aborting.
- *[[FS-06-2]]FS-06-2* _(Entity-access)_ For each valid transcript, write a session to <<E-01,E-01 Session>> with <<E-01.4,E-01.4 origin>> (origin) set to `pilot`, <<E-01.6,E-01.6 displayable>> (displayable) set to true, and <<E-01.7,E-01.7 consentGranted>> (consentGranted) set to true. <<E-01.10,E-01.10 tosAgreed>> (tosAgreed) and <<E-01.11,E-01.11 projectionConsent>> (projectionConsent) are left unset — pilot sessions have no visitor to ask, and displayable is set directly rather than derived from a projection consent that doesn't apply here.
- *[[FS-06-3]]FS-06-3* _(Entity-access)_ Write each exchange to <<E-02,E-02 Exchange>> in transcript order.
- *[[FS-06-4]]FS-06-4* _(Function-call)_ Call <<TF-05,TF-05 Derive a scenario statement>> for each session to derive its scenario statement.
- *[[FS-06-4a]]FS-06-4a* _(Entity-access)_ If the transcript supplies a title, write it to <<E-01.12,E-01.12 title>> as-is (no length bound, same as <<TF-07,TF-07 Refine a session title>>'s own output). Optional — a transcript that omits it leaves the field unset, same as any session whose title hasn't been generated yet, and xref:L2-system-design-concept.adoc#SE-02[SE-02 Display client] falls back to the scenario line in that case.
- *[[FS-06-4b]]FS-06-4b* _(Entity-access)_ If the transcript supplies a `reply_to` naming another seed in the same import, link this session's first exchange to that seed's most recent exchange and increment its <<E-02.7,E-02.7 replyCount>>, exactly as a visitor opening a session from that exchange's QR code would. Optional — a transcript that omits it imports as a standalone session. Seeds are read in two passes (plain seeds first, `reply_to` seeds second) so the link resolves regardless of file order; a `reply_to` seed may not itself be a reply target.
- *[[FS-06-5]]FS-06-5* _(Data-operation)_ Return per-transcript outcomes.

*Alternative flows*

- *[[FA-06-1]]FA-06-1* _(extends <<FS-06-1,FS-06-1>>)_ A transcript is malformed. It is recorded as rejected and the import continues with the remainder. _Outcome:_ Resume.
- *[[FA-06-2]]FA-06-2* _(extends <<FS-06-4b,FS-06-4b>>)_ A transcript's `reply_to` names no plain seed in the import (unknown name, or it points at another `reply_to` seed). The transcript is recorded as rejected rather than imported without its link, and the import continues with the remainder. _Outcome:_ Resume.

=== [[TF-07]]TF-07 Refine a session title

_Detail level:_ Narrative

Called once per session by <<TI-06,TI-06 Refine a session title>>, after the session's first exchange exists. Attempts a short title via <<TO-02,TO-02 Request a classification>> with a title-generation instruction asking for brevity (a short phrase, not a full sentence) but no fixed length; on any failure (timeout, malformed response, or any other exception) falls back to the same trim-based derivation <<TF-05,TF-05 Derive a scenario statement>> uses for the scenario statement, just unbounded instead of capped at <<TF-05,TF-05 Derive a scenario statement>>'s own bound. Either path always produces a usable title — there is no "couldn't generate one" outcome from the caller's point of view. Writes the result to <<E-01.12,E-01.12 title>> once and never recomputes it: called again for a session that already has one, it returns the stored value unchanged rather than repeating the provider call. Two consumers read the result: xref:L2-system-design-concept.adoc#SE-01[SE-01 Input client]'s own header (its original purpose), and, once written, <<TF-04,TF-04 Assemble display material>> picks it up for xref:L2-system-design-concept.adoc#SE-02[SE-02 Display client]'s title line — the latter is read-only here; this function has no SE-02-specific behavior, it just happens to be read by both. No goal relation: this is presentation logic, not a stated business goal.

=== [[TF-08]]TF-08 Record a session evaluation

_Detail level:_ Stepwise +
_Achieves:_ <<G-07,G-07 Capture optional session feedback without gating>>

- *[[FS-08-1]]FS-08-1* _(Data-operation)_ Discard any rating answer whose question key isn't one of the configured set, or whose value falls outside the configured scale. A caller sending a stale or tampered question set loses only the parts that don't fit, not the whole submission.
- *[[FS-08-2]]FS-08-2* _(Data-operation)_ If nothing survives <<FS-08-1,FS-08-1>> and no feedback text was supplied, stop without writing anything.
- *[[FS-08-3]]FS-08-3* _(Entity-access)_ Otherwise, write the surviving answers and any feedback text to <<E-04,E-04 Session evaluation>>, replacing a prior submission for the same session if one exists.

*Alternative flows*

- *[[FA-08-1]]FA-08-1* _(extends <<FS-08-3,FS-08-3>>)_ The session identifier is unknown. Nothing is written. _Outcome:_ Terminate.

=== [[TF-09]]TF-09 Extend a session's turn allowance

_Detail level:_ Stepwise +
_Achieves:_ <<G-02,G-02 Keep a session usable across interruption>>

- *[[FS-09-1]]FS-09-1* _(Entity-access)_ Resolve the session from <<E-01,E-01 Session>>. If it is unknown or expired, stop without writing anything.
- *[[FS-09-2]]FS-09-2* _(Entity-access)_ Add one base `TURN_ALLOWANCE` to <<E-01.13,E-01.13 bonusTurns>> (bonusTurns) and refresh <<E-01.9,E-01.9 lastActiveAt>> (lastActiveAt) in the same write. The effective ceiling <<FS-01-3,FS-01-3>> checks rises by that amount; <<E-01.8,E-01.8 turnCount>> is untouched, so prior exchanges keep their positions.
- *[[FS-09-3]]FS-09-3* _(Data-operation)_ Return the reopened session state and the new remaining count.

No request-rate limit or generation cost attaches to this function — it is one bounded write. It is deliberately not capped per session: what it lifts is a ceiling on turns that each already cost a rate- and size-limited provider call (<<TF-01,TF-01 Process a visitor turn>>), and a visitor wanting more turns can already start a fresh session.

*Alternative flows*

- *[[FA-09-1]]FA-09-1* _(extends <<FS-09-1,FS-09-1>>)_ The session identifier is unknown or expired. Nothing is written. _Outcome:_ Terminate.

'''

== Technical interfaces (inbound)

=== [[TI-01]]TI-01 Open a session

_Call type:_ Synchronous +
_Calling elements:_ xref:L2-system-design-concept.adoc#SE-01[SE-01 Input client] (xref:L3-SE-01-input-client.adoc#TO-01[TO-01 Open a session]) +
_Input:_ Three consent booleans, optional as a group; absent on creation, all three required together on the decision call: agreement to take part, retention consent, projection consent. +
_Output:_ Session identifier (string), turn allowance (integer), session state (enum), origin (enum). Origin is always included — cheap to compute, and consumed only by xref:L2-system-design-concept.adoc#SE-01[SE-01 Input client]'s own debug-mode display (xref:L3-SE-01-input-client.adoc#QR-06[QR-06 Diagnostic detail is available to an operator]), not gated on this side. +
_Action:_ Creates a session in <<E-01,E-01 Session>> with origin fixed as `live` and a generated identifier, or records the three-part decision against an existing session by writing <<E-01.7,E-01.7 consentGranted>>, <<E-01.10,E-01.10 tosAgreed>>, and <<E-01.11,E-01.11 projectionConsent>> — and sets <<E-01.6,E-01.6 displayable>> (displayable) directly from the projection choice in the same write. Returns immediately. +
_Error cases:_

- Malformed request: missing or non-boolean value on any of the three, on the decision call.
- Agreement to take part is false or absent: rejected before it becomes a stored state (unlike the other two, which are legitimate declines) — this is what makes participation itself, as opposed to retention or projection, a precondition rather than an opt-out.
- Session unknown: the identifier supplied with a decision does not resolve.

=== [[TI-02]]TI-02 Submit a contribution

_Call type:_ Synchronous +
_Calling elements:_ xref:L2-system-design-concept.adoc#SE-01[SE-01 Input client] (xref:L3-SE-01-input-client.adoc#TO-02[TO-02 Submit a contribution]) +
_Input:_ Session identifier (string, required), contribution text (string, required). +
_Output:_ The completed exchange (visitor contribution and Sparring response), remaining turn allowance (integer), session state (enum). Returned once generation has completed. Every response, regardless of outcome, also carries rate-limit remaining (integer, from <<TF-03,TF-03 Enforce request limits>>); an `ok` response additionally carries generation time in milliseconds (from <<FS-01-8,FS-01-8>>'s timing), and a flagged response carries the moderation reason (from <<TF-02,TF-02 Assess a contribution for projection suitability>>'s outcome — `blocked-term`, `contains-personal-information`, `targets-real-person`, or `llm-classification` if the classifier call itself failed). All three are cheap to compute and are included unconditionally. The exact reason is consumed only by xref:L2-system-design-concept.adoc#SE-01[SE-01 Input client]'s own debug-mode display (xref:L3-SE-01-input-client.adoc#QR-06[QR-06 Diagnostic detail is available to an operator]); xref:L2-system-design-concept.adoc#SE-01[SE-01 Input client]'s standard (non-debug) UI derives a coarser two-category hint from the same value — see xref:L3-SE-01-input-client.adoc#QR-06[QR-06 Diagnostic detail is available to an operator]'s note. +
_Action:_ Calls <<TF-01,TF-01 Process a visitor turn>> with the session identifier and contribution, and returns its result. Response time is dominated by the provider call in <<TF-01,TF-01 Process a visitor turn>> <<FS-01-8,FS-01-8>> and is expected to run to several seconds. +
_Error cases:_

- Request limit reached (from <<TF-03,TF-03 Enforce request limits>>).
- Session unknown or expired.
- Turn limit reached.
- Contribution rejected: empty or over-length.
- Contribution flagged: unsuitable per <<TF-02,TF-02 Assess a contribution for projection suitability>> (<<FA-01-2,FA-01-2>>) — distinct from generation-failed. The visitor edits and resubmits; nothing about the session changes.
- Generation failed: any condition grouped by <<FA-01-1,FA-01-1>>.

IMPORTANT: Unlike the earlier design this superseded, the response's condition list is not silent about suitability — a flagged contribution is a distinct, visible outcome (<<FA-01-2,FA-01-2>>), because the visitor needs to know to edit their message. What the response never carries is which specific field or word triggered the flag, or anything about sessions other than the caller's own. The visitor-facing UI does, deliberately, distinguish two broad categories — personal information versus inappropriate content — from the moderation reason; that coarse hint is not the same as exposing the exact classification or wordlist match, which stays debug-only (xref:L3-SE-01-input-client.adoc#QR-06[QR-06 Diagnostic detail is available to an operator] in L3-SE-01-input-client.adoc).

== Quality requirements

=== [[QR-01]]QR-01 Generation is bounded and its bound is enforced here _(Performance)_

_Applies to:_ <<TF-01,TF-01 Process a visitor turn>>, <<TO-01,TO-01 Request a Sparring response>> +
_Acceptance criteria:_ <<TF-01,TF-01 Process a visitor turn>> abandons a generation request at a fixed bound and returns a generation-failed condition. The bound is 20 seconds (`GENERATION_TIMEOUT_SECONDS`, config.php), below xref:L2-system-design-concept.adoc#SE-01[SE-01 Input client]'s own 25-second wait bound so that this element decides the outcome rather than the client timing out first. +
_Supports:_ xref:L2-system-design-concept.adoc#SQR-01[SQR-01 A Sparring response arrives, or its absence is visible]

=== [[QR-02]]QR-02 Restarts unattended _(Availability)_

_Applies to:_ The element overall +
_Acceptance criteria:_ The process restarts automatically after failure. No in-memory state is required for correctness after a restart, because everything needed is in <<E-01,E-01 Session>> through <<E-03,E-03 Rate limit window>>. +
_Supports:_ xref:L2-system-design-concept.adoc#SQR-02[SQR-02 The installation recovers without a person present]

=== [[QR-03]]QR-03 A rejected request affects only its own session _(Availability)_

_Applies to:_ <<TF-01,TF-01 Process a visitor turn>>, <<TF-03,TF-03 Enforce request limits>> +
_Acceptance criteria:_ Rate limiting, turn limits, and generation failures return a condition for the requesting session and leave every other session serviceable. +
_Supports:_ xref:L2-system-design-concept.adoc#SQR-02[SQR-02 The installation recovers without a person present]

=== [[QR-04]]QR-04 The provider credential never leaves the host _(Security)_

_Applies to:_ <<TO-01,TO-01 Request a Sparring response>>, <<TO-02,TO-02 Request a classification>> +
_Acceptance criteria:_ The credential is read from host configuration, is absent from version control, and appears in no response body, error message, or log line. +
_Supports:_ xref:L2-system-design-concept.adoc#SQR-04[SQR-04 Credentials and quota are protected from the public]

=== [[QR-05]]QR-05 Limits are enforced on every path _(Security)_

_Applies to:_ <<TF-01,TF-01 Process a visitor turn>>, <<TF-03,TF-03 Enforce request limits>>, <<TI-02,TI-02 Submit a contribution>> +
_Acceptance criteria:_ Contribution length, session turn allowance, and request rate are each checked in this element regardless of whether a client has already checked them. +
_Supports:_ xref:L2-system-design-concept.adoc#SQR-04[SQR-04 Credentials and quota are protected from the public]

=== [[QR-06]]QR-06 Origin is written once _(Data-integrity)_

_Applies to:_ <<E-01,E-01 Session>>, <<TF-06,TF-06 Import pilot transcripts>>, <<TI-01,TI-01 Open a session>> +
_Acceptance criteria:_ <<E-01.4,E-01.4 origin>> is set at creation and no code path updates it. No process infers origin from any other value. +
_Supports:_ xref:L2-system-design-concept.adoc#SQR-05[SQR-05 Origin is fixed at creation and never inferred]

=== [[QR-07]]QR-07 No partial exchange is ever stored _(Data-integrity)_

_Applies to:_ <<TF-01,TF-01 Process a visitor turn>> +
_Acceptance criteria:_ <<E-02,E-02 Exchange>> is written only after a response has been received. Every failure path in <<FS-01-8,FS-01-8>> writes nothing. +
_Supports:_ xref:L2-system-design-concept.adoc#SQR-05[SQR-05 Origin is fixed at creation and never inferred] +
_Element specific:_ Yes

=== [[QR-08]]QR-08 Suitability assessment fails closed _(Compliance)_

_Applies to:_ <<TF-02,TF-02 Assess a contribution for projection suitability>> +

=== [[C-01]]C-01 PHP with a file-backed store on one instance _(Technical)_

_Source:_ xref:L2-system-design-concept.adoc#SC-01[SC-01 PHP with a file-backed store on a single hosted]. +
_Applies to:_ The element overall, <<E-01,E-01 Session>> through <<E-03,E-03 Rate limit window>>. +
_Acceptance criteria:_ Runs as a single process group against a single store file, with no external database, cache, or queue service. +
_Consequence:_ Rules out any design requiring concurrent write scaling or a background worker. Long-running work must complete within the request, which is why <<TF-01,TF-01 Process a visitor turn>> is synchronous, why <<TF-05,TF-05 Derive a scenario statement>> caches its result rather than recomputing, and why <<TF-07,TF-07 Refine a session title>>'s title refinement is triggered by a dedicated client call (<<TI-06,TI-06 Refine a session title>>) rather than a server-side background job — there is no queue or worker process for xref:L2-system-design-concept.adoc#SE-01[SE-01 Input client] to hand it to. +
_Implements:_ xref:L2-system-design-concept.adoc#SC-01[SC-01 PHP with a file-backed store on a single hosted]

=== [[C-02]]C-02 Provider limits bound the element's own limits _(Integration)_

_Source:_ xref:L2-system-design-concept.adoc#SC-04[SC-04 Generation is rate-limited and metered by the provider]. +
_Applies to:_ <<TF-03,TF-03 Enforce request limits>>, <<TF-01,TF-01 Process a visitor turn>>. +
_Acceptance criteria:_ The request rate threshold in <<TF-03,TF-03 Enforce request limits>> is set below the provider's limit, so that visitors meet this element's limit rather than the provider's. +
_Consequence:_ Rules out unthrottled forwarding. Sets an upper bound on concurrent visitors: 10 requests per 60-second window per origin (<<TF-03,TF-03 Enforce request limits>>). +
_Implements:_ xref:L2-system-design-concept.adoc#SC-04[SC-04 Generation is rate-limited and metered by the provider]

=== [[C-03]]C-03 The operator path is not publicly reachable _(Security)_

=== [[C-04]]C-04 No administrative interface, no analytics layer _(Business)_

_Source:_ xref:L2-system-design-concept.adoc#SC-03[SC-03 Build effort is capped and the piece is expendable]. +
_Applies to:_ The element overall. +
_Acceptance criteria:_ Operator tasks — seeding, extraction, pruning, reset, and backup — are performed directly against the host and the store file, each its own single-purpose script (`bin/import_pilot.php`, `bin/export.php`, `bin/prune_orphaned_sessions.php`, `bin/reset_db.php`, `bin/backup_db.php`). +
_Consequence:_ Rules out building any surface for inspecting or moderating sessions during the exhibition. Extraction is a query against the store; pruning and reset are, respectively, a targeted and a bulk delete against the same store; backup is a file-level snapshot; pruning and reset are guarded by an explicit confirmation flag rather than by any authentication this system otherwise has no use for (<<C-03,C-03 The operator path is not publicly reachable>>). +
_Implements:_ xref:L2-system-design-concept.adoc#SC-03[SC-03 Build effort is capped and the piece is expendable]

=== [[C-05]]C-05 Attempts to bypass the Sparring stance are not filtered _(Business)_

_Source:_ xref:L2-system-design-concept.adoc#AP-07[AP-07 Attempts to argue the Sparring partner out of its]. +
_Applies to:_ <<TF-02,TF-02 Assess a contribution for projection suitability>>. +
_Acceptance criteria:_ The classification instruction distinguishes hostility directed at the Sparring partner (suitable, however extreme the tone) from harmful content targeting a real person or group (targets-real-person). A visitor arguing the Sparring partner out of its position, however hostile, produces a suitable classification. The instruction also states the exercise's actual subject matter explicitly (<<TF-02,TF-02 Assess a contribution for projection suitability>>) — necessary alongside the target-based distinction, not instead of it; found missing in testing, where its absence alone caused on-topic contributions to fail this same acceptance criterion from the other direction. +
_Consequence:_ There is no off-topic filter of any kind — disengagement (spam, unrelated chat) is not classified or withheld. Sessions in which the friction is successfully talked away are retained and projected like any other (subject to the visitor's own projection consent, xref:L2-system-design-concept.adoc#SC-05[SC-05 Retention requires consent; projection requires]). +
_Element specific:_ Yes

=== [[C-06]]C-06 Classifier input is untrusted data, not instruction _(Security)_

_Source:_ this review. +
_Applies to:_ <<TF-02,TF-02 Assess a contribution for projection suitability>>. +
_Acceptance criteria:_ The contribution text is delimited and labeled as data in the classification prompt, and delimiter characters that could close that boundary are stripped from the contribution before assembly. +
_Consequence:_ Distinct from <<C-05,C-05 Attempts to bypass the Sparring stance are not filtered>> — that constraint accepts persona-steering as the exhibit's own subject; this one closes the separate case of a contribution engineered to flip the moderation verdict itself, which has no comparable justification for staying open. +
_Element specific:_ Yes
