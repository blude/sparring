= Element Design Concept: Backend Service

*Element:* xref:L2-system-design-concept.adoc#SE-03[SE-03] Backend service +
*Element profile:* Backend service / API +
*Parent:* System Design Concept +
*Status:* Draft

*Sections that apply.* Goals, use cases, both technical interface sections, technical functions, entities, quality requirements, and constraints. User interfaces do not apply: this element has no human-facing surface. Its only human actor is xref:L2-system-design-concept.adoc#UT-03[UT-03], who reaches it through the operator interface (<<TI-05,TI-05>>) rather than through a UI.

*A note on the datastore.* Per xref:L2-system-design-concept.adoc#AP-04[AP-04], storage is held inside this element rather than identified as a separate software element at L2. Its entities are therefore specified here, in section 7.

'''

== 1. Goals

*[[G-01]]G-01 — Produce Sparring responses and hold every rule that governs them* +
The element shall be the sole location of generation, moderation, rate limiting, and session policy, so that no rule is editable from a device the project does not control. +
_Success criteria (qualitative):_ No client contains a provider credential or any limit the element does not independently enforce. +
_Satisfies:_ xref:L2-system-design-concept.adoc#SG-01[SG-01], xref:L2-system-design-concept.adoc#SG-04[SG-04]

*[[G-02]]G-02 — Keep a session usable across interruption* +
The element shall resolve a session identifier to its full state and history for as long as the session is live. +
_Success criteria (qualitative):_ A session fetched after an interruption returns identical content to what its participant last saw. +
_Satisfies:_ xref:L2-system-design-concept.adoc#SG-03[SG-03]

*[[G-03]]G-03 — Persist every interaction with its origin fixed at creation* +
The element shall record sessions and exchanges tagged pilot or live at the moment of creation, with no later assignment or correction. +
_Success criteria (qualitative):_ Exhibition material is extractable by filtering one stored value. +
_Satisfies:_ xref:L2-system-design-concept.adoc#SG-05[SG-05]

*[[G-04]]G-04 — Decide what may be stored, and let the visitor's own choice decide what may be projected* +
The element shall assess each contribution for suitability before it is stored, rejecting an unsuitable one so the visitor can edit and resubmit rather than silently hiding it after the fact. Whether a _stored_ exchange is projected is then a separate question, answered by the visitor's own projection consent, not by re-running suitability at display time. +
_Success criteria (qualitative):_ Nothing unsuitable is ever stored. A session that declined projection consent never appears on the wall regardless of content; a session that granted it does, for as long as its content keeps passing the write-time check. +
_Satisfies:_ xref:L2-system-design-concept.adoc#SG-07[SG-07]

*[[G-05]]G-05 — Keep the display surface populated* +
The element shall supply display material at all times, falling back to pilot-origin sessions when insufficient live material is eligible. +
_Success criteria (qualitative):_ The display feed is never empty while the element is running and pilot material exists. +
_Satisfies:_ xref:L2-system-design-concept.adoc#SG-06[SG-06]

*[[G-06]]G-06 — Absorb load and misuse without failing* +
The element shall reject excess requests, over-length contributions, and over-long sessions as expected conditions, and shall continue serving other visitors when it does. +
_Success criteria (qualitative):_ A rejected request affects only its own session. +
_Satisfies:_ xref:L2-system-design-concept.adoc#SG-04[SG-04]

'''

== 2. Use cases

Use cases at this level are thin, because most of this element's behaviour is reached through technical interfaces rather than as user-facing functionality. The one exception is the operator path, which is a genuine use case with a human actor.

=== [[UC-01]]UC-01 — The operator seeds pilot material

_Actors:_ xref:L2-system-design-concept.adoc#UT-03[UT-03] +
_Prerequisites:_ Pilot transcripts exist in the expected structured form. +
_Achieves:_ <<G-03,G-03>>, <<G-05,G-05>> +
_Realises:_ SSc-03

- *[[ST-01-1]]ST-01-1* _(Activity)_ xref:L2-system-design-concept.adoc#UT-03[UT-03] places a transcript file where the element can read it and invokes the import path (<<TI-05,TI-05>>).
- *[[ST-01-2]]ST-01-2* _(Function-call)_ The element calls <<TF-06,TF-06>> with the file contents. <<TF-06,TF-06>> validates each transcript, creates its session and exchanges with origin fixed as pilot, and returns a per-transcript outcome.
- *[[ST-01-3]]ST-01-3* _(Activity)_ The element reports how many transcripts were imported and names any that were rejected.

*Alternative scenarios*

- *[[EX-01-1]]EX-01-1* _(extends <<ST-01-2,ST-01-2>>)_ One or more transcripts are malformed. Those are rejected and named; the remainder are imported. The import does not abort. _Outcome:_ Alternative-success.

*Note.* This path performs no generation and never calls xref:L2-system-design-concept.adoc#PE-01[PE-01]. The Sparring responses already exist in the transcripts, and regenerating them would produce material that no pilot session actually contained.

'''

== 3. User interfaces

Not applicable. This element presents no user interface. xref:L2-system-design-concept.adoc#UT-03[UT-03] reaches it through <<TI-05,TI-05>>, which is a technical interface invoked directly on the host rather than a surface.

'''

== 4. Technical functions

*[[TF-01]]TF-01 — Process a visitor turn* +
_Detail level:_ Stepwise +
_Achieves:_ <<G-01,G-01>>, <<G-04,G-04>>, <<G-06,G-06>>

The element's central function. Everything that happens between a visitor pressing submit and a response returning is here, which is what keeps retry and error handling in one place rather than scattered across interfaces.

- *[[FS-01-1]]FS-01-1* _(Function-call)_ Call <<TF-03,TF-03>> with the request origin. If it reports the limit reached, return that condition and stop.
- *[[FS-01-2]]FS-01-2* _(Entity-access)_ Read the session from <<E-01,E-01>> by its identifier (<<E-01.1,E-01.1>>). If absent or expired, return a session-unknown condition and stop.
- *[[FS-01-3]]FS-01-3* _(Data-operation)_ Compare <<E-01.8,E-01.8>> (turnCount) against the session turn allowance. If the allowance is exhausted, return a turn-limit condition and stop.
- *[[FS-01-4]]FS-01-4* _(Data-operation)_ Trim the contribution and check it against the length bound. If it is empty or over-length, return a rejected condition and stop. No provider call has been made at this point, which matters because this is the cheapest rejection path and the one most likely to fire.
- *[[FS-01-5]]FS-01-5* _(Function-call)_ Call <<TF-02,TF-02>> with the contribution. <<TF-02,TF-02>> returns a suitability outcome.
- *[[FS-01-6]]FS-01-6* _(Data-operation)_ If <<TF-02,TF-02>> reported the contribution unsuitable, return a content-flagged condition and stop. Nothing is written to <<E-01,E-01>> or <<E-02,E-02>>, and no provider call for a response is made — this is the same cheap-rejection reasoning as <<FS-01-4,FS-01-4>>, just one check later. The session itself is not altered; only this turn is rejected.
- *[[FS-01-7]]FS-01-7* _(Entity-access)_ Read the session's prior exchanges from <<E-02,E-02>> (<<E-02.3,E-02.3>>, <<E-02.4,E-02.4>>) in order, to supply conversational context.
- *[[FS-01-8]]FS-01-8* _(Outbound-call)_ Call <<TO-01,TO-01>> with the Sparring system prompt, the prior exchanges, and the new contribution. Expect a response text. _Call behaviour:_ Synchronous. Timeout TBC, to be set from measured response times (xref:L2-system-design-concept.adoc#SQR-01[SQR-01]). Two attempts, with a short delay between them, on transport failure, timeout, or a provider 5xx. *No retry on a provider rate-limit or quota response*, because retrying a rate limit deepens it; return a generation-failed condition immediately. *No retry on a content-policy refusal from the provider*, which is a determinate outcome rather than a transient fault. On exhausted attempts, return a generation-failed condition. Nothing is written to <<E-02,E-02>> on any failure path, so a failed turn leaves no partial exchange in the record.
- *[[FS-01-9]]FS-01-9* _(Entity-access)_ Write a new exchange to <<E-02,E-02>> carrying the contribution (<<E-02.3,E-02.3>>), the response (<<E-02.4,E-02.4>>), the session reference (<<E-02.2,E-02.2>>), and its position (<<E-02.5,E-02.5>>).
- *[[FS-01-10]]FS-01-10* _(Entity-access)_ Increment <<E-01.8,E-01.8>> (turnCount) and update <<E-01.9,E-01.9>> (lastActiveAt).
- *[[FS-01-11]]FS-01-11* _(Function-call)_ If this was the session's first exchange, call <<TF-05,TF-05>> to derive the scenario statement and write it to <<E-01.5,E-01.5>>.
- *[[FS-01-12]]FS-01-12* _(Data-operation)_ Return the response, the remaining turn allowance, and the session state.

*Alternative flows*

- *[[FA-01-1]]FA-01-1* _(extends <<FS-01-8,FS-01-8>>)_ Provider rate limit, quota exhaustion, timeout, transport failure after retries, or content-policy refusal. All return a generation-failed condition to the caller and write nothing. Grouping is deliberate: the calling client takes the same action for every one of these, and distinguishing them would produce a taxonomy nobody acts on. The distinction is preserved in logs rather than in the response. _Outcome:_ Terminate.
- *[[FA-01-2]]FA-01-2* _(extends <<FS-01-6,FS-01-6>>)_ The contribution is unsuitable. Unlike <<FA-01-1,FA-01-1>>, this is not terminal — the caller (xref:L2-system-design-concept.adoc#SE-01[SE-01]) tells the visitor to edit and resubmit, and the input field re-enables with the text preserved. _Outcome:_ Resume.

*[[TF-02]]TF-02 — Assess a contribution for projection suitability* +
_Detail level:_ Stepwise +
_Achieves:_ <<G-04,G-04>>

Determines whether a contribution may be stored and answered at all — and, because only stored content can ever be projected (<<G-04,G-04>>), this is also what keeps unsuitable material off the public surface. It determines whether _this turn_ proceeds, not whether the visitor's session does: on an unsuitable result the visitor edits and resubmits, they are not cut off.

- *[[FS-02-1]]FS-02-1* _(Data-operation)_ Check the contribution against a maintained term list covering profanity. A match returns unsuitable without a provider call.
- *[[FS-02-2]]FS-02-2* _(Outbound-call)_ Call <<TO-02,TO-02>> with the contribution and a classification instruction. Expect one of: suitable, contains-personal-information, targets-real-person. _Call behaviour:_ Synchronous, short timeout, single attempt, no retry. *On any failure, return unsuitable.* Failing closed is correct here: the cost of not projecting a suitable contribution is that one item is missing from a wall, and the cost of projecting an unsuitable one is unrecoverable once it is six feet tall in a public room.
- *[[FS-02-3]]FS-02-3* _(Data-operation)_ Map the classification to an outcome and return it.

*The distinction this function must get right (xref:L2-system-design-concept.adoc#AP-07[AP-07]).* _Targets-real-person_ means the harmful content — hate speech, harassment, threats, sexual content — is aimed at or about a real, identifiable person or group. It does *not* mean a visitor who is hostile toward, arguing with, pressuring, or instructing the Sparring partner to abandon its position, however extreme the tone — the Sparring partner is software, not a person, and that visitor is engaged with the exercise; their attempt is the observation the installation exists to produce. The classification instruction must state this distinction explicitly rather than leaving it to the model's default reading of "unsafe language", because hostility-at-the-AI and harm-at-a-person can otherwise look similar and only one should be withheld.

*A second distinction the instruction must also get right, found in testing.* Stating the xref:L2-system-design-concept.adoc#AP-07[AP-07] distinction was not enough on its own: without also stating what the exercise's subject matter actually _is_, the classifier had nothing to check arguing-the-exercise against, which produced misclassifications in the other direction. Both the topic itself and the target-based carve-out need to be explicit in the instruction — omitting either produces a failure mode this requirement exists to prevent, from a different direction.

_Contains-personal-information_ covers names, contact details, and health, financial, or comparably personal circumstances. This case is expected to arise most often in exactly the situation xref:L2-system-design-concept.adoc#AP-07[AP-07] protects: a visitor under real pressure disclosing something real while trying to get the system to relent. That turn is rejected and not stored; the visitor edits it and continues — the session is not ended over it.

*[[TF-03]]TF-03 — Enforce request limits* +
_Detail level:_ Narrative +
_Achieves:_ <<G-06,G-06>>

Reads the current window for the request origin from <<E-03,E-03>>, increments it, and reports whether the allowance is exceeded. Windows are keyed on a hashed origin (<<E-03.1,E-03.1>>), so no raw address is stored. Expired windows are reset in place rather than swept by a separate process, which avoids a scheduled job on an unattended host. Threshold and window length are TBC, to be set below the provider's own limits per xref:L2-system-design-concept.adoc#SC-04[SC-04]. No goal relation beyond <<G-06,G-06>>: this is a guard, not business logic.

*[[TF-04]]TF-04 — Assemble display material* +
_Detail level:_ Stepwise +
_Achieves:_ <<G-05,G-05>>, <<G-04,G-04>>

Produces the ordered items the projection renders. Every decision about what appears on the wall is made here, so that xref:L2-system-design-concept.adoc#SE-02[SE-02] carries no policy (xref:L3-SE-02-display-client.adoc#C-02[C-02] of that element).

- *[[FS-04-1]]FS-04-1* _(Entity-access)_ Read live-origin sessions from <<E-01,E-01>> where <<E-01.6,E-01.6>> (displayable) is true and at least one exchange exists, ordered by <<E-01.9,E-01.9>> (lastActiveAt) descending, up to the item limit.
- *[[FS-04-2]]FS-04-2* _(Data-operation)_ If fewer items were found than the limit, continue at <<FS-04-3,FS-04-3>>. Otherwise continue at <<FS-04-4,FS-04-4>>.
- *[[FS-04-3]]FS-04-3* _(Entity-access)_ Read pilot-origin sessions from <<E-01,E-01>> under the same eligibility conditions, ordered by <<E-01.9,E-01.9>> descending, and append until the limit is reached.
- *[[FS-04-4]]FS-04-4* _(Entity-access)_ For each selected session, read its most recent exchange from <<E-02,E-02>> (<<E-02.3,E-02.3>>, <<E-02.4,E-02.4>>). Which exchange to select is an open decision (xref:L2-system-design-concept.adoc#SE-02[SE-02] xref:L3-SE-02-display-client.adoc#TBC-04[TBC-04]); it is made here and changing it does not affect xref:L2-system-design-concept.adoc#SE-02[SE-02].
- *[[FS-04-5]]FS-04-5* _(Data-operation)_ Build each item from the session's scenario (<<E-01.5,E-01.5>>), the exchange pair, the origin (<<E-01.4,E-01.4>>), and a recency position. Return the ordered list.

*[[TF-05]]TF-05 — Derive a scenario statement* +
_Detail level:_ Narrative +
_Achieves:_ <<G-05,G-05>>

Produces the short context line shown above an exchange, from the session's first visitor contribution. The initial approach is to trim that contribution to a bounded length, which costs nothing. If opening contributions prove to read badly as context lines when checked against pilot transcripts, the fallback is a single generation call via <<TO-02,TO-02>>, with the result written once to <<E-01.5,E-01.5>> and never recomputed. Computing it per render would multiply provider cost by the polling rate, which is the specific mistake this note exists to prevent.

*[[TF-06]]TF-06 — Import pilot transcripts* +
_Detail level:_ Stepwise +
_Achieves:_ <<G-03,G-03>>, <<G-05,G-05>>

- *[[FS-06-1]]FS-06-1* _(Data-operation)_ Parse the supplied file and validate each transcript's structure. Collect malformed ones for reporting rather than aborting.
- *[[FS-06-2]]FS-06-2* _(Entity-access)_ For each valid transcript, write a session to <<E-01,E-01>> with <<E-01.4,E-01.4>> (origin) set to `pilot`, <<E-01.6,E-01.6>> (displayable) set to true, and <<E-01.7,E-01.7>> (consentGranted) set to true. <<E-01.10,E-01.10>> (tosAgreed) and <<E-01.11,E-01.11>> (projectionConsent) are left unset — pilot sessions have no visitor to ask, and displayable is set directly rather than derived from a projection consent that doesn't apply here.
- *[[FS-06-3]]FS-06-3* _(Entity-access)_ Write each exchange to <<E-02,E-02>> in transcript order.
- *[[FS-06-4]]FS-06-4* _(Function-call)_ Call <<TF-05,TF-05>> for each session to derive its scenario statement.
- *[[FS-06-5]]FS-06-5* _(Data-operation)_ Return per-transcript outcomes.

*Alternative flows*

- *[[FA-06-1]]FA-06-1* _(extends <<FS-06-1,FS-06-1>>)_ A transcript is malformed. It is recorded as rejected and the import continues with the remainder. _Outcome:_ Resume.

*[[TF-07]]TF-07 — Refine a session title* +
_Detail level:_ Narrative

Called once per session by <<TI-06,TI-06>>, after the session's first exchange exists. Attempts a short (≤38 character) title via <<TO-02,TO-02>> with a title-generation instruction; on any failure (timeout, malformed response, or any other exception) falls back to the same trim-based derivation <<TF-05,TF-05>> uses for the scenario statement, just capped at 38 characters instead of <<TF-05,TF-05>>'s own bound. Either path always produces a usable title — there is no "couldn't generate one" outcome from the caller's point of view. Writes the result to <<E-01.12,E-01.12>> once and never recomputes it: called again for a session that already has one, it returns the stored value unchanged rather than repeating the provider call. No goal relation: like <<TF-04,TF-04>> in xref:L2-system-design-concept.adoc#SE-01[SE-01], this is presentation logic serving xref:L2-system-design-concept.adoc#SE-01[SE-01]'s header, not a stated business goal.

'''

== 5. Technical interfaces (inbound)

*[[TI-01]]TI-01 — Open a session* +
_Call type:_ Synchronous +
_Calling elements:_ xref:L2-system-design-concept.adoc#SE-01[SE-01] (xref:L3-SE-01-input-client.adoc#TO-01[TO-01]) +
_Input:_ Three consent booleans, optional as a group; absent on creation, all three required together on the decision call: agreement to take part, retention consent, projection consent. +
_Output:_ Session identifier (string), turn allowance (integer), session state (enum), origin (enum). Origin is always included — cheap to compute, and consumed only by xref:L2-system-design-concept.adoc#SE-01[SE-01]'s own debug-mode display (xref:L3-SE-01-input-client.adoc#QR-06[QR-06]), not gated on this side. +
_Action:_ Creates a session in <<E-01,E-01>> with origin fixed as `live` and a generated identifier, or records the three-part decision against an existing session by writing <<E-01.7,E-01.7>>, <<E-01.10,E-01.10>>, and <<E-01.11,E-01.11>> — and sets <<E-01.6,E-01.6>> (displayable) directly from the projection choice in the same write. Returns immediately. +
_Error cases:_

- Malformed request: missing or non-boolean value on any of the three, on the decision call.
- Agreement to take part is false or absent: rejected before it becomes a stored state (unlike the other two, which are legitimate declines) — this is what makes participation itself, as opposed to retention or projection, a precondition rather than an opt-out.
- Session unknown: the identifier supplied with a decision does not resolve.

*[[TI-02]]TI-02 — Submit a contribution* +
_Call type:_ Synchronous +
_Calling elements:_ xref:L2-system-design-concept.adoc#SE-01[SE-01] (xref:L3-SE-01-input-client.adoc#TO-02[TO-02]) +
_Input:_ Session identifier (string, required), contribution text (string, required). +
_Output:_ The completed exchange (visitor contribution and Sparring response), remaining turn allowance (integer), session state (enum). Returned once generation has completed. Every response, regardless of outcome, also carries rate-limit remaining (integer, from <<TF-03,TF-03>>); an `ok` response additionally carries generation time in milliseconds (from <<FS-01-8,FS-01-8>>'s timing), and a flagged response carries the moderation reason (from <<TF-02,TF-02>>'s outcome — `blocked-term`, `contains-personal-information`, `targets-real-person`, or `llm-classification` if the classifier call itself failed). All three are cheap to compute and are included unconditionally. The exact reason is consumed only by xref:L2-system-design-concept.adoc#SE-01[SE-01]'s own debug-mode display (xref:L3-SE-01-input-client.adoc#QR-06[QR-06]); xref:L2-system-design-concept.adoc#SE-01[SE-01]'s standard (non-debug) UI derives a coarser two-category hint from the same value — see xref:L3-SE-01-input-client.adoc#QR-06[QR-06]'s note. +
_Action:_ Calls <<TF-01,TF-01>> with the session identifier and contribution, and returns its result. Response time is dominated by the provider call in <<TF-01,TF-01>> <<FS-01-8,FS-01-8>> and is expected to run to several seconds. +
_Error cases:_

- Request limit reached (from <<TF-03,TF-03>>).
- Session unknown or expired.
- Turn limit reached.
- Contribution rejected: empty or over-length.
- Contribution flagged: unsuitable per <<TF-02,TF-02>> (<<FA-01-2,FA-01-2>>) — distinct from generation-failed. The visitor edits and resubmits; nothing about the session changes.
- Generation failed: any condition grouped by <<FA-01-1,FA-01-1>>.

_Unlike the earlier design this superseded, the response's condition list is not silent about suitability — a flagged contribution is a distinct, visible outcome (<<FA-01-2,FA-01-2>>), because the visitor needs to know to edit their message. What the response never carries is which specific field or word triggered the flag, or anything about sessions other than the caller's own. The visitor-facing UI does, deliberately, distinguish two broad categories — personal information versus inappropriate content — from the moderation reason; that coarse hint is not the same as exposing the exact classification or wordlist match, which stays debug-only (xref:L3-SE-01-input-client.adoc#QR-06[QR-06] in L3-SE-01-input-client.adoc)._

*[[TI-03]]TI-03 — Retrieve a session* +
_Call type:_ Synchronous +
_Calling elements:_ xref:L2-system-design-concept.adoc#SE-01[SE-01] (xref:L3-SE-01-input-client.adoc#TO-03[TO-03]) +
_Input:_ Session identifier (string, required). +
_Output:_ Session state (enum), turn allowance and remaining count (integers), ordered exchanges (array), whether the consent decision has been recorded (boolean) — one flag covering all three parts, since they are always recorded together — and origin (enum), same rationale as <<TI-01,TI-01>>'s. +
_Action:_ Reads the session from <<E-01,E-01>> and its exchanges from <<E-02,E-02>> in order. Returns immediately. +
_Error cases:_

- Session unknown or expired.

*[[TI-04]]TI-04 — Retrieve display material* +
_Call type:_ Synchronous +
_Calling elements:_ xref:L2-system-design-concept.adoc#SE-02[SE-02] (xref:L3-SE-02-display-client.adoc#TO-01[TO-01]) +
_Input:_ None. +
_Output:_ An ordered list of items, each carrying a session identifier, scenario statement, one visitor contribution, one Sparring response, an origin value, and a recency position. +
_Action:_ Calls <<TF-04,TF-04>> and returns its result. Returns immediately. +
_Error cases:_ None specific to this interface. An empty list is a valid response and occurs only when no pilot material has been imported.

_This interface takes no parameters by design. Item count, ordering, exchange selection, and pilot fallback are all decided in <<TF-04,TF-04>>, so that a change to any of them requires no change in xref:L2-system-design-concept.adoc#SE-02[SE-02] and no coordination between the two._

*[[TI-05]]TI-05 — Import pilot material* +
_Call type:_ Synchronous +
_Calling elements:_ xref:L2-system-design-concept.adoc#UT-03[UT-03], directly on the host. +
_Input:_ A structured transcript file. +
_Output:_ Per-transcript outcomes: imported or rejected, with a reason for each rejection. +
_Action:_ Calls <<TF-06,TF-06>>. Not reachable over the public endpoint (<<C-03,C-03>>). +
_Error cases:_

- File unreadable or unparseable in full.
- Individual transcript malformed, reported per transcript rather than as a failure of the call.

*[[TI-06]]TI-06 — Refine a session title* +
_Call type:_ Synchronous +
_Calling elements:_ xref:L2-system-design-concept.adoc#SE-01[SE-01] (xref:L3-SE-01-input-client.adoc#TO-04[TO-04]) +
_Input:_ Session identifier (string, required). +
_Output:_ Refined title (string) — always present when the call succeeds. +
_Action:_ Calls <<TF-07,TF-07>> and returns its result. Returns once the provider call (or its fallback) completes. +
_Error cases:_

- Session unknown.
- Malformed request.
- No exchange yet exists for the session — the caller normally only invokes this after the first exchange completes.

'''

== 6. Technical interfaces (outbound)

*[[TO-01]]TO-01 — Request a Sparring response* +
_Statement:_ This interface obtains a Sparring partner reply to a visitor contribution by calling the language generation API (xref:L2-system-design-concept.adoc#PE-01[PE-01]). Used for every visitor turn. The system prompt instructs the model to reply in whichever language (English or German) the visitor's own contribution is written in — a prompt-level behavior, not a parameter of this interface, and independent of xref:L2-system-design-concept.adoc#SE-01[SE-01]'s UI locale (xref:L3-SE-01-input-client.adoc#QR-08[QR-08] in L3-SE-01-input-client.adoc). +
_Input:_ The Sparring system prompt, the session's prior exchanges as conversational context, the new visitor contribution, and generation parameters. +
_Output:_ Response text. +
_Error cases:_ Rate limit exceeded. Quota exhausted. Content-policy refusal. Provider server error. Timeout. Transport failure. Authentication failure. +
_Authoritative spec:_ Provider documentation. No element in this system holds the authoritative specification. +
_Calls:_ xref:L2-system-design-concept.adoc#PE-01[PE-01]

*[[TO-02]]TO-02 — Request a classification* +
_Statement:_ This interface obtains a suitability classification, a scenario statement, or a session title for a visitor contribution, by calling the language generation API (xref:L2-system-design-concept.adoc#PE-01[PE-01]). Used by <<TF-02,TF-02>> on every turn, by <<TF-05,TF-05>> only if the trimmed-contribution approach proves inadequate, and by <<TF-07,TF-07>> once per session. +
_Input:_ The contribution text and a classification instruction, a summarisation instruction, or a title-generation instruction. +
_Output:_ A classification value, a short statement, or a short title. +
_Error cases:_ As <<TO-01,TO-01>>. +
_Authoritative spec:_ Provider documentation. +
_Calls:_ xref:L2-system-design-concept.adoc#PE-01[PE-01]

_Call behaviour is specified on the calling function steps (<<TF-01,TF-01>> <<FS-01-8,FS-01-8>>, <<TF-02,TF-02>> <<FS-02-2,FS-02-2>>), or in the calling function's own narrative for <<TF-07,TF-07>>, not here. The three differ substantially: <<TF-01,TF-01>> retries and fails open to an error the visitor sees; <<TF-02,TF-02>> does not retry and fails closed to unsuitable; <<TF-07,TF-07>> does not retry and fails open to a trim-based fallback, never an error._

'''

== 7. Entities

*[[E-01]]E-01 — Session* +
_Persistence:_ Persistent +
_Refines:_ xref:L1-solution-design-concept.adoc#BE-01[BE-01]

[options="header"]
|===
| ID | Attribute | Type | Required | Description
| [[E-01.1]]E-01.1 | sessionId | string | required | Generated identifier, sufficiently random to resist enumeration. Travels in the client address (xref:L2-system-design-concept.adoc#AP-03[AP-03]), so it is not secret and nothing sensitive may be derived from it.
| [[E-01.2]]E-01.2 | createdAt | datetime | required | When the session was created.
| [[E-01.3]]E-01.3 | scenarioSource | enum | required | `first-contribution` or `generated`. Records how <<E-01.5,E-01.5>> was produced, so a later change of approach is visible in the data.
| [[E-01.4]]E-01.4 | origin | enum | required | `pilot` or `live`. Written at creation and never modified (xref:L2-system-design-concept.adoc#SQR-05[SQR-05]).
| [[E-01.5]]E-01.5 | scenario | string | optional | The context line shown with the exchange. Absent until the first exchange exists.
| [[E-01.6]]E-01.6 | displayable | boolean | required | Whether the session may appear on the projection. Defaults false; set directly from <<E-01.11,E-01.11>> (projectionConsent) when the consent decision is recorded — not by moderation. Nothing unsuitable can reach <<E-02,E-02>> in the first place (<<G-04,G-04>>/xref:L2-system-design-concept.adoc#AP-05[AP-05]), so there is no separate moderation-driven display flag to maintain. Independent of <<E-01.7,E-01.7>>.
| [[E-01.7]]E-01.7 | consentGranted | boolean | optional | Whether the participant agreed to retention. Absent until the decision is recorded. Independent of <<E-01.6,E-01.6>> (xref:L2-system-design-concept.adoc#SQR-06[SQR-06]).
| [[E-01.8]]E-01.8 | turnCount | integer | required | Exchanges completed. Compared against the turn allowance.
| [[E-01.9]]E-01.9 | lastActiveAt | datetime | required | Time of the most recent exchange. Drives display ordering and expiry.
| [[E-01.10]]E-01.10 | tosAgreed | boolean | optional | Whether the participant agreed to the terms of participation. Absent until recorded; once recorded it is always true — a decline is rejected at <<TI-01,TI-01>> before it becomes a stored value (unlike <<E-01.7,E-01.7>> and <<E-01.11,E-01.11>>, which legitimately store `false`).
| [[E-01.11]]E-01.11 | projectionConsent | boolean | optional | Whether the participant agreed to projection. Absent until the decision is recorded. Drives <<E-01.6,E-01.6>> directly. Independent of <<E-01.7,E-01.7>> — a session may be retained and not projected, or projected and not retained.
| [[E-01.12]]E-01.12 | title | string | optional | Short (≤38 character) header title, refined once from the first contribution and never recomputed (<<TF-07,TF-07>>). Absent until refined.
|===

_E-01.6, <<E-01.7,E-01.7>>, and <<E-01.11,E-01.11>> govern three separate things: whether the public surface may currently show this session, whether it may be kept after the exhibition, and the visitor's own projection choice — the first is now derived from the third, the second stays fully independent of both. <<E-01.10,E-01.10>> is different in kind from the other two consent fields: it gates participation itself rather than a data-processing purpose, which is why it is never stored as a decline (see L1 xref:L1-solution-design-concept.adoc#BC-02[BC-02], L2 xref:L2-system-design-concept.adoc#SC-05[SC-05])._

== 8. Quality requirements

*[[QR-01]]QR-01 — Generation is bounded and its bound is enforced here* _(Performance)_ +
_Applies to:_ <<TF-01,TF-01>>, <<TO-01,TO-01>> +
_Acceptance criteria:_ <<TF-01,TF-01>> abandons a generation request at a fixed bound and returns a generation-failed condition. The bound is TBC, to be set from measured response times, and must be below xref:L2-system-design-concept.adoc#SE-01[SE-01]'s own wait bound so that the element decides the outcome rather than the client timing out first. +
_Supports:_ xref:L2-system-design-concept.adoc#SQR-01[SQR-01]

*[[QR-02]]QR-02 — Restarts unattended* _(Availability)_ +
_Applies to:_ The element overall +
_Acceptance criteria:_ The process restarts automatically after failure. No in-memory state is required for correctness after a restart, because everything needed is in <<E-01,E-01>> through <<E-03,E-03>>. +
_Supports:_ xref:L2-system-design-concept.adoc#SQR-02[SQR-02]

*[[QR-03]]QR-03 — A rejected request affects only its own session* _(Availability)_ +
_Applies to:_ <<TF-01,TF-01>>, <<TF-03,TF-03>> +
_Acceptance criteria:_ Rate limiting, turn limits, and generation failures return a condition for the requesting session and leave every other session serviceable. +
_Supports:_ xref:L2-system-design-concept.adoc#SQR-02[SQR-02]

*[[QR-04]]QR-04 — The provider credential never leaves the host* _(Security)_ +
_Applies to:_ <<TO-01,TO-01>>, <<TO-02,TO-02>> +
_Acceptance criteria:_ The credential is read from host configuration, is absent from version control, and appears in no response body, error message, or log line. +
_Supports:_ xref:L2-system-design-concept.adoc#SQR-04[SQR-04]

*[[QR-05]]QR-05 — Limits are enforced on every path* _(Security)_ +
_Applies to:_ <<TF-01,TF-01>>, <<TF-03,TF-03>>, <<TI-02,TI-02>> +
_Acceptance criteria:_ Contribution length, session turn allowance, and request rate are each checked in this element regardless of whether a client has already checked them. +
_Supports:_ xref:L2-system-design-concept.adoc#SQR-04[SQR-04]

*[[QR-06]]QR-06 — Origin is written once* _(Data-integrity)_ +
_Applies to:_ <<E-01,E-01>>, <<TF-06,TF-06>>, <<TI-01,TI-01>> +
_Acceptance criteria:_ <<E-01.4,E-01.4>> is set at creation and no code path updates it. No process infers origin from any other value. +
_Supports:_ xref:L2-system-design-concept.adoc#SQR-05[SQR-05]

*[[QR-07]]QR-07 — No partial exchange is ever stored* _(Data-integrity)_ +
_Applies to:_ <<TF-01,TF-01>> +
_Acceptance criteria:_ <<E-02,E-02>> is written only after a response has been received. Every failure path in <<FS-01-8,FS-01-8>> writes nothing. +
_Supports:_ xref:L2-system-design-concept.adoc#SQR-05[SQR-05] +
_Element specific:_ Yes

*[[QR-08]]QR-08 — Suitability assessment fails closed* _(Compliance)_ +
_Applies to:_ <<TF-02,TF-02>> +
_Acceptance criteria:_ Every failure of <<TF-02,TF-02>>, including provider unavailability, yields an unsuitable outcome. No path treats an unavailable classifier as permission to project. +
_Supports:_ xref:L2-system-design-concept.adoc#SQR-06[SQR-06]

*[[QR-09]]QR-09 — Projection eligibility and retention consent are never conflated* _(Compliance)_ +
_Applies to:_ <<E-01,E-01>>, <<TF-01,TF-01>>, <<TF-04,TF-04>>, <<TI-01,TI-01>> +
_Acceptance criteria:_ <<E-01.7,E-01.7>> (retention) is read and written independently of <<E-01.6,E-01.6>>/<<E-01.11,E-01.11>> (projection). <<E-01.6,E-01.6>> is permitted to derive from <<E-01.11,E-01.11>> — that is the one intentional coupling, recorded once at consent time, not re-derived elsewhere — but no path derives <<E-01.7,E-01.7>> from either, or <<E-01.11,E-01.11>> from <<E-01.7,E-01.7>>. +
_Supports:_ xref:L2-system-design-concept.adoc#SQR-06[SQR-06]

*[[QR-10]]QR-10 — No raw request origin is stored* _(Compliance)_ +
_Applies to:_ <<E-03,E-03>>, <<TF-03,TF-03>> +
_Acceptance criteria:_ Only the hashed origin is written. The raw value exists in memory for the duration of the request and nowhere else. +
_Element specific:_ Yes

== 9. Constraints

*[[C-01]]C-01 — PHP with a file-backed store on one instance* _(Technical)_ +
_Source:_ xref:L2-system-design-concept.adoc#SC-01[SC-01]. +
_Applies to:_ The element overall, <<E-01,E-01>> through <<E-03,E-03>>. +
_Acceptance criteria:_ Runs as a single process group against a single store file, with no external database, cache, or queue service. +
_Consequence:_ Rules out any design requiring concurrent write scaling or a background worker. Long-running work must complete within the request, which is why <<TF-01,TF-01>> is synchronous, why <<TF-05,TF-05>> caches its result rather than recomputing, and why <<TF-07,TF-07>>'s title refinement is triggered by a dedicated client call (<<TI-06,TI-06>>) rather than a server-side background job — there is no queue or worker process for xref:L2-system-design-concept.adoc#SE-01[SE-01] to hand it to. +
_Implements:_ xref:L2-system-design-concept.adoc#SC-01[SC-01]

*[[C-02]]C-02 — Provider limits bound the element's own limits* _(Integration)_ +
_Source:_ xref:L2-system-design-concept.adoc#SC-04[SC-04]. +
_Applies to:_ <<TF-03,TF-03>>, <<TF-01,TF-01>>. +
_Acceptance criteria:_ The request rate threshold in <<TF-03,TF-03>> is set below the provider's limit, so that visitors meet this element's limit rather than the provider's. +
_Consequence:_ Rules out unthrottled forwarding. Sets an upper bound on concurrent visitors, TBC once the threshold is chosen. +
_Implements:_ xref:L2-system-design-concept.adoc#SC-04[SC-04]

*[[C-03]]C-03 — The operator path is not publicly reachable* _(Security)_ +
_Source:_ xref:L2-system-design-concept.adoc#SC-03[SC-03], and the absence of any authentication in this system. +
_Applies to:_ <<TI-05,TI-05>>. +
_Acceptance criteria:_ <<TI-05,TI-05>> is invoked on the host and is not routed on the public endpoint. +
_Consequence:_ Rules out remote import and, with it, the need for an authentication mechanism this system otherwise has no use for. Seeding requires host access. +
_Element specific:_ Yes

*[[C-04]]C-04 — No administrative interface, no analytics layer* _(Business)_ +
_Source:_ xref:L2-system-design-concept.adoc#SC-03[SC-03]. +
_Applies to:_ The element overall. +
_Acceptance criteria:_ Operator tasks — seeding, extraction, pruning, reset, and backup — are performed directly against the host and the store file, each its own single-purpose script (`bin/import_pilot.php`, `bin/export.php`, `bin/prune_orphaned_sessions.php`, `bin/reset_db.php`, `bin/backup_db.php`). +
_Consequence:_ Rules out building any surface for inspecting or moderating sessions during the exhibition. Extraction is a query against the store; pruning and reset are, respectively, a targeted and a bulk delete against the same store; backup is a file-level snapshot; pruning and reset are guarded by an explicit confirmation flag rather than by any authentication this system otherwise has no use for (<<C-03,C-03>>). +
_Implements:_ xref:L2-system-design-concept.adoc#SC-03[SC-03]

*[[C-05]]C-05 — Attempts to bypass the Sparring stance are not filtered* _(Business)_ +
_Source:_ xref:L2-system-design-concept.adoc#AP-07[AP-07]. +
_Applies to:_ <<TF-02,TF-02>>. +
_Acceptance criteria:_ The classification instruction distinguishes hostility directed at the Sparring partner (suitable, however extreme the tone) from harmful content targeting a real person or group (targets-real-person). A visitor arguing the Sparring partner out of its position, however hostile, produces a suitable classification. The instruction also states the exercise's actual subject matter explicitly (<<TF-02,TF-02>>) — necessary alongside the target-based distinction, not instead of it; found missing in testing, where its absence alone caused on-topic contributions to fail this same acceptance criterion from the other direction. +
_Consequence:_ There is no off-topic filter of any kind — disengagement (spam, unrelated chat) is not classified or withheld. Sessions in which the friction is successfully talked away are retained and projected like any other (subject to the visitor's own projection consent, xref:L2-system-design-concept.adoc#SC-05[SC-05]). +
_Element specific:_ Yes

*[[C-06]]C-06 — Classifier input is untrusted data, not instruction* _(Security)_ +
_Source:_ this review. +
_Applies to:_ <<TF-02,TF-02>>. +
_Acceptance criteria:_ The contribution text is delimited and labeled as data in the classification prompt, and delimiter characters that could close that boundary are stripped from the contribution before assembly. +
_Consequence:_ Distinct from <<C-05,C-05>> — that constraint accepts persona-steering as the exhibit's own subject; this one closes the separate case of a contribution engineered to flip the moderation verdict itself, which has no comparable justification for staying open. +
_Element specific:_ Yes
