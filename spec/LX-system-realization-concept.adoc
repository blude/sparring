== Detailed architecture diagram

Implementation-level companion to
xref:L2-system-design-concept.adoc[L2]'s own Architecture diagram, which is
deliberately minimal (no datastore box, no SE-04 box — see that section's
note). This one adds the routes, `src/` components, and infrastructure
detail that belongs here rather than at L2, per the framework's own
deployment-detail rule. Boxes carry the same element IDs as L2 so the two
diagrams can be checked against each other; sub-boxes inside an element are
implementation detail, not separate modeled elements.

Reading it: two thin clients (`SE-01`/`SE-02`) hold no logic beyond
presentation — every rule (moderation, rate limits, session policy, the API
credential) lives in `SE-03`, and `SE-03`'s only outbound dependency is
`PE-01`. `data/store.db` is a single SQLite file inside the backend
process, not a separate service; `prompts/sparring.md` (`SE-04`) is
supplied as content on the outbound call, not a component with its own
network edge. No websocket/SSE connection — the wall polls
`/api/recent-exchanges` on an interval instead.
