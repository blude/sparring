== Goals

=== [[G-01]]G-01 Make turn-taking visible to people who are not participating

The element shall present visitor contributions and Sparring responses as paired exchanges, so that an observer sees a challenge and what provoked it rather than an isolated reply. +
_Success criteria (qualitative):_ An observer reading one projected item can tell that the AI declined to simply resolve the request. +
_Satisfies:_ xref:L2-system-design-concept.adoc#SG-02[SG-02 Make turn-taking readable from across the room]

=== [[G-02]]G-02 Remain populated at all times

The element shall never present an empty or near-empty surface while running, including before the first visitor of the day and between live sessions. +
_Success criteria (qualitative):_ The projection carries readable content continuously from start-up onward. +
_Satisfies:_ xref:L2-system-design-concept.adoc#SG-06[SG-06 Never present an empty surface]

=== [[G-03]]G-03 Stay readable and stable without attention

The element shall run for the duration of exhibition hours without reload, recover from backend interruption on its own, and update without visible redraw of unchanged content. +
_Success criteria (qualitative):_ No operator action is required at any point during opening hours. Unchanged items do not flicker or reflow on update. +
_Satisfies:_ xref:L2-system-design-concept.adoc#SG-02[SG-02 Make turn-taking readable from across the room], xref:L2-system-design-concept.adoc#SG-06[SG-06 Never present an empty surface] +
_Rationale:_ xref:L2-system-design-concept.adoc#SQR-02[SQR-02 The installation recovers without a person present]. A projection that visibly redraws every few seconds reads as a status screen rather than as part of the work.

=== [[G-04]]G-04 Distinguish concurrent visitors from one another

The element shall label each item so an observer can tell exchanges from different sessions apart, even when several appear in the same view. +
_Success criteria (qualitative):_ An observer looking at two items can tell whether they belong to the same visitor or different ones, without reading the content of either. +
_Satisfies:_ xref:L2-system-design-concept.adoc#SG-02[SG-02 Make turn-taking readable from across the room] +
_Rationale:_ Readability (xref:L2-system-design-concept.adoc#SG-02[SG-02 Make turn-taking readable from across the room]) previously meant "legible text" but not "distinguishable speaker" — every item carried the identical literal label "Visitor —", so two concurrent sessions were indistinguishable except by content. That gap is what this goal closes.

'''

== Use cases

=== [[UC-01]]UC-01 An observer reads the projection

_Actors:_ xref:L2-system-design-concept.adoc#UT-02[UT-02 Observing visitor], xref:L2-system-design-concept.adoc#SE-03[SE-03 Backend service] +
_Prerequisites:_ The element is running and has completed at least one successful retrieval. +
_Achieves:_ <<G-01,G-01 Make turn-taking visible to people who are not>>, <<G-02,G-02 Remain populated at all times>>, <<G-03,G-03 Stay readable and stable without attention>>, <<G-04,G-04 Distinguish concurrent visitors from one another>> +
_Realises:_ SSc-02

xref:L2-system-design-concept.adoc#UT-02[UT-02 Observing visitor] performs no action in this use case. The steps describe the element's own cycle, which is what determines what an observer sees at any moment.

- *[[ST-01-1]]ST-01-1* _(Function-call)_ On a fixed interval, the element calls <<TF-01,TF-01 Retrieve display material>>, which retrieves current display material from xref:L2-system-design-concept.adoc#SE-03[SE-03 Backend service].
- *[[ST-01-2]]ST-01-2* _(Function-call)_ The element calls <<TF-02,TF-02 Reconcile against what is displayed>> with the retrieved material. <<TF-02,TF-02 Reconcile against what is displayed>> compares it against what is currently shown and determines what has changed.
- *[[ST-01-3]]ST-01-3* _(Function-call)_ For each item that is new or changed, the element calls <<TF-03,TF-03 Fit an item to the available space>>, which fits the item to the available space.
- *[[ST-01-4]]ST-01-4* _(Activity)_ The element applies the changes, giving prominence to newly arrived material and receding older material. Unchanged items are left untouched.
- *[[ST-01-5]]ST-01-5* _(User-interaction)_ xref:L2-system-design-concept.adoc#UT-02[UT-02 Observing visitor] reads the surface. No input is available or expected.

*Alternative scenarios*

- *[[EX-01-1]]EX-01-1* _(extends <<ST-01-1,ST-01-1>>)_ Retrieval fails. The element retains what it is currently showing and retries on the next interval. Nothing on the surface indicates the failure, because an error message on a gallery wall is worse than slightly stale content. _Outcome:_ Resume.
- *[[EX-01-2]]EX-01-2* _(extends <<ST-01-2,ST-01-2>>)_ The retrieved material is identical to what is shown. The element does nothing. _Outcome:_ Terminate.
- *[[EX-01-3]]EX-01-3* _(extends <<ST-01-1,ST-01-1>>)_ Retrieval has failed continuously for a sustained period. The element continues showing its last material indefinitely rather than clearing. _Resolved: no threshold, no action._ The projector was never actually run at the exhibition (connectivity issues on-site), so this path never got exercised in practice. No threshold or operator alert was built, and none is judged worth building speculatively — a silent, indefinitely-stale wall is not a critical failure (the piece's actual interaction is on the visitor's own phone, xref:L2-system-design-concept.adoc#SE-01[SE-01 Input client]; the wall is a bonus surface). Revisit only if a future exhibition actually runs the projection and this becomes a real operational problem. _Outcome:_ Resume.

'''

== User interfaces

=== [[UI-01]]UI-01 Projection surface

_User type:_ xref:L2-system-design-concept.adoc#UT-02[UT-02 Observing visitor] +
_Realises:_ <<UC-01,UC-01 An observer reads the projection>>

The whole projected area. No controls, no cursor, no navigation, no scroll. The surface is a fixed viewport whose contents change over time.

*Baseline composition (agreed, build against this).* <<TBC-01,TBC-01 Treatment of prominence and recency.>> currently adopts a masonry arrangement (column count per display profile — see <<C-03,C-03 Fixed target resolution, one of a set of named display profiles>>): each session is placed once into whichever column holds the fewest items, ties broken by least rendered height, and stays there for its lifetime. Every item has the same shape: a title line (the refined title, falling back to the scenario line — <<E-01.7,E-01.7 title>>/<<E-01.2,E-01.2 scenario>>), then a visitor contribution, then the Sparring response. One exchange pair per session, so each session contributes exactly one item.

Two properties of this baseline are settled and should not be revisited without a reason:

- *The exchange pair is the unit.* A single turn shown alone conveys nothing about friction. The pair is the smallest thing that shows the mechanism.
- *Every item has the same shape.* A design that renders the newest session differently from the rest requires two layouts, two truncation rules, and a decision about what happens when the newest session is unusually long. Uniformity removes all three. This is about shared _template and truncation rule_, not shared rendered height — height already varied with content length under the single-column baseline, and still does under masonry; that variance is what breaks ties between columns holding the same number of items, not a departure from uniformity.

A header above the wall carries the logo, a live clock, and a total session/exchange count. The clock is rendered entirely client-side from the system clock and the resolved locale — it reflects no backend data and needs no entity or interface entry of its own. The counts do come from xref:L2-system-design-concept.adoc#SE-03[SE-03 Backend service] (<<E-02,E-02 Wall statistics>>) and are listed in *Visible data* below.

*Visible data*

[options="header"]
|===
| Item | Type | Displayed | Source | Conditions
| Title line | string | What the session is about, giving an isolated exchange its context — the AI-refined session title (xref:L3-SE-03-backend-service.adoc#TF-07[TF-07 Refine a session title]) when one exists, falling back to the cruder scenario line until it does | <<E-01.7,E-01.7 title>>, falling back to <<E-01.2,E-01.2 scenario>> | Per item, always

*Actions.* None. The element accepts no input.

*Input fields.* None.

*Navigation.* None.

=== Open decisions

_Source:_ xref:L2-system-design-concept.adoc#SC-06[SC-06 The projected layout is an open decision]

Each was deliberately deferred until real pilot transcripts could be seen on xref:L2-system-design-concept.adoc#HE-02[HE-02 Projection setup] at exhibition viewing distance. None of them changed the interface xref:L2-system-design-concept.adoc#SE-03[SE-03 Backend service] provides, so they were resolved after the rest of the system worked. The exhibition has since run; all six are resolved below.

*[[TBC-01]]TBC-01 Treatment of prominence and recency.* _Resolved: masonry._ Four candidates were considered; masonry shipped as the baseline and ran unchanged through the exhibition (`venue` display profile — 2 columns, 12-item limit, `config.php`). No pilot observation surfaced a reason to reconsider. The other three, for the record:

- _Size gradient._ Newest item largest, older items progressively smaller and dimmer. Conveys accumulation well. Weakness: older items become texture rather than content, so most of the surface is not actually readable.
- _Rotation._ One or two items at full size, cycling on a timer, with an indicator of how many others exist. Every item gets a turn at being readable. Weakness: loses the sense of accumulation, and requires a live-session priority rule so that a visitor who has just contributed sees their own exchange rather than waiting for the cycle.
- _Hybrid._ A large primary region plus a thin strip of recent items. Retains both properties at the cost of more layout work.
- _Masonry (adopted, shipped)._ `DISPLAY_COLUMNS` columns (per display profile, config.php), each item placed once into the column holding the fewest items — ties broken by least rendered height — and never moved. Balancing by count first, height only as the tiebreaker: pure height-based placement skews badly whenever the number of items on the wall is below the columns' combined capacity and item heights vary, piling short items into one column and leaving the rest sparse. Every item stays equally readable (no gradient, no cycling), and filling the columns evenly gives a natural sense of accumulation without a timer. Weakness: strict global recency ordering is lost — a session's column position no longer says "newer than everything below it," only "newer than what's below it in its own column." Chosen for now because it needs no dwell-time rule (<<TBC-03,TBC-03 Dwell time, if any.>>) and no live-session interrupt rule (<<TBC-02,TBC-02 Whether a live session interrupts.>>), unlike rotation/hybrid.
+
Masonry has its own version of "does everyone get seen," distinct from <<TBC-02,TBC-02 Whether a live session interrupts.>>: with the display profile's item limit and selection by most-recent-activity (`Store::getDisplayableSessions`, `ORDER BY last_active_at DESC`), a session that goes quiet is _excluded_, not merely delayed — it can drop off the wall entirely if enough other sessions stay more active. Accepted as intentional: recency-eviction gives visitors a reason to keep engaging rather than submitting once and disengaging, which fits a piece about friction. Not revisited unless pilot observation shows visitors feeling unfairly dropped rather than prompted to continue.

*[[TBC-02]]TBC-02 Whether a live session interrupts.* _Resolved: not applicable._ Only applicable if <<TBC-01,TBC-01 Treatment of prominence and recency.>> resolved to rotation or hybrid. It resolved to masonry instead, where the analogous question is answered above — no live-session interrupt rule was ever needed or built.

*[[TBC-03]]TBC-03 Dwell time, if any.* _Resolved: not applicable._ Moot for the same reason as <<TBC-02,TBC-02 Whether a live session interrupts.>>: masonry items never rotate, so there is nothing to dwell on. No dwell-time constant exists in `config.php`.

*[[TBC-04]]TBC-04 Which exchange pair per session.* _Resolved: most recent, unchanged._ Checked against the exhibition's live data (49 sessions): most sessions never exceed one or two exchanges, so there is usually no alternative pair to choose from; in the sessions that ran three or more, Sparring's pushback consistently sharpened with each turn rather than peaking early, so the most recent pair stayed the more demonstrative one. xref:L2-system-design-concept.adoc#SE-03[SE-03 Backend service] keeps supplying it unchanged. (A related but distinct item stays open in `TODO.md`: suppressing a session's first exchange from the wall when it is only the opening scenario prompt — a display-omission question, not a which-pair question, and doesn't block this.)

*[[TBC-05]]TBC-05 Item count and truncation.* _Resolved: character bound._ Fixed item count per display profile (`itemLimit`, `config.php`) plus a per-side character bound shipped and ran for the full exhibition. Rendered-height measurement was never needed.

*[[TBC-06]]TBC-06 Whether pilot-origin items are visually distinguishable.* _Resolved: left unmarked._ Origin stays off the normal surface, visible only behind the operator debug flag (`arena.js`, <<QR-07,QR-07 Diagnostic tag is available to an operator>>) — the "keep the surface uniform" option above.

'''

== Technical functions

=== [[TF-01]]TF-01 Retrieve display material

_Detail level:_ Stepwise +
_Achieves:_ <<G-02,G-02 Remain populated at all times>>, <<G-03,G-03 Stay readable and stable without attention>>

- *[[FS-01-1]]FS-01-1* _(Outbound-call)_ Call <<TO-01,TO-01 Retrieve display material>> for current display material. _Call behaviour:_ Synchronous, no retry within a cycle, timeout shorter than the polling interval so that requests cannot overlap. A failure is not escalated: the function returns the previous material unchanged. Consecutive failures are counted for <<TBC-03,TBC-03 Dwell time, if any.>> but trigger no action. Polling interval is 4 seconds (`DISPLAY_POLL_INTERVAL_SECONDS`, config.php).
- *[[FS-01-2]]FS-01-2* _(Data-operation)_ Validate that the response has the expected shape. Discard it entirely if not, rather than rendering a partial surface.
- *[[FS-01-3]]FS-01-3* _(Data-operation)_ Return the material for reconciliation.

*Alternative flows*

- *[[FA-01-1]]FA-01-1* _(extends <<FS-01-1,FS-01-1>>)_ Timeout, transport failure, or an unexpected status. Return the currently held material, increment the failure count, and take no other action. Grouping is intentional: the element's response is the same for every failure mode. _Outcome:_ Resume.

=== [[TF-02]]TF-02 Reconcile against what is displayed

_Detail level:_ Stepwise +
_Achieves:_ <<G-03,G-03 Stay readable and stable without attention>>

Determines the minimum change needed, so that unchanged items are not redrawn. This function is the whole reason the projection does not flicker.

- *[[FS-02-1]]FS-02-1* _(Entity-access)_ Read the currently displayed items from <<E-01,E-01 Displayed material>>.
- *[[FS-02-2]]FS-02-2* _(Data-operation)_ Match retrieved items against displayed items by session identifier (<<E-01.1,E-01.1 sessionId>>).
- *[[FS-02-3]]FS-02-3* _(Data-operation)_ Produce three sets: items to add, items whose content has changed, and items to remove. An item present in both with identical content appears in none of them.
- *[[FS-02-4]]FS-02-4* _(Entity-access)_ Write the new set to <<E-01,E-01 Displayed material>> once the changes have been applied.

=== [[TF-03]]TF-03 Fit an item to the available space

_Detail level:_ Narrative +
_Achieves:_ <<G-01,G-01 Make turn-taking visible to people who are not>>

Trims an item's contribution and response so that the item occupies its allotted space without overflow, preserving enough of both halves that the exchange still reads as an exchange. Trimming only one side would leave a challenge with no visible provocation, which defeats <<G-01,G-01 Make turn-taking visible to people who are not>>. The initial approach is a character bound per side; rendered-height measurement is the fallback if that proves inadequate (<<TBC-05,TBC-05 Item count and truncation.>>).

=== [[TF-04]]TF-04 Render the surface

_Detail level:_ Narrative +
_Achieves:_ <<G-04,G-04 Distinguish concurrent visitors from one another>>

Applies the reconciled changes to <<UI-01,UI-01 Projection surface>> with transitions on entry, recession, and exit. All content from xref:L2-system-design-concept.adoc#SE-03[SE-03 Backend service] is inserted as text, never as markup. Each item's visitor alias is derived once from its session identifier (<<E-01.1,E-01.1 sessionId>>) at the point the item is first added — never recomputed on update, since the value is invariant for a given session and recomputing it would be pure waste.

The entry transition is restricted to opacity and transform, and applies only to a node <<TF-02,TF-02 Reconcile against what is displayed>> placed in the add set — never to a node <<TF-02,TF-02 Reconcile against what is displayed>> placed in the update set. A node in the update set instead gets a brief in-place pulse (also transform-only) on the same node, marking that its content changed without re-adding or moving it. Both are compositor-only, so neither an entering nor an updating item can shift or redraw any other item on the surface, which is what keeps this consistent with <<QR-02,QR-02 Unchanged content does not redraw>> rather than in tension with it — <<QR-02,QR-02 Unchanged content does not redraw>> protects _other_ items from disturbance, not whether a changed item itself may carry a cue. A session occupies one node for its lifetime: only its first exchange goes through the add path; every exchange after that is an update to that same node. No sound accompanies this element: it runs unattended (<<QR-03,QR-03 Runs unattended for the full opening period>>), with no user gesture available to unlock audio playback.

'''

== Technical interfaces (outbound)

=== [[TO-01]]TO-01 Retrieve display material

_Statement:_ This interface obtains the set of sessions currently eligible for projection by calling the backend service (xref:L2-system-design-concept.adoc#SE-03[SE-03 Backend service]). Used on every polling cycle. +
_Input:_ The display-profile identifier the element was loaded with (`?d=<name>` on the address; absent means the default profile), forwarded verbatim. This names _which physical screen_ the request is for — it is not a selection, ordering, or prominence parameter. The profile-to-item-count mapping is resolved entirely in xref:L2-system-design-concept.adoc#SE-03[SE-03 Backend service] (xref:L3-SE-03-backend-service.adoc#TI-04[TI-04 Retrieve display material]), so item selection remains a backend decision and this element still carries no policy (<<C-02,C-02 This element holds no selection or ordering policy>>). +
_Output:_ An ordered list of items, each carrying a session identifier, a scenario statement, an optional refined title, one visitor contribution, one Sparring response, an origin value, and a recency marker; alongside the list, a total session count (integer, <<E-02.1,E-02.1 sessionCount>>) and a total exchange count (integer, <<E-02.2,E-02.2 exchangeCount>>). +
_Error cases:_ Service unavailable. Malformed or unexpected response shape. +
_Authoritative spec:_ xref:L2-system-design-concept.adoc#SE-03[SE-03 Backend service] element design, xref:L3-SE-03-backend-service.adoc#TI-04[TI-04 Retrieve display material].

NOTE: No `Calls → PE-` relation applies. This element reaches no partner element.

'''

== Quality requirements

=== [[QR-01]]QR-01 Readable at exhibition viewing distance _(Usability)_

_Applies to:_ <<UI-01,UI-01 Projection surface>> +
_Acceptance criteria (qualitative):_ A complete exchange is readable by a standing observer at the room's typical viewing distance, verified on xref:L2-system-design-concept.adoc#HE-02[HE-02 Projection setup] in the exhibition space before opening. Not verified in a browser window. +
_Supports:_ xref:L2-system-design-concept.adoc#SQR-03[SQR-03 The projection is readable at exhibition viewing]

=== [[QR-02]]QR-02 Unchanged content does not redraw _(Usability)_

_Applies to:_ <<TF-02,TF-02 Reconcile against what is displayed>>, <<TF-04,TF-04 Render the surface>> +
_Acceptance criteria:_ An update that adds one item leaves every other item visually undisturbed. No full-surface repaint occurs on a polling cycle. +
_Supports:_ xref:L2-system-design-concept.adoc#SQR-03[SQR-03 The projection is readable at exhibition viewing]

=== [[QR-03]]QR-03 Runs unattended for the full opening period _(Availability)_

_Applies to:_ The element overall +
_Acceptance criteria (qualitative):_ Runs for the duration of exhibition hours without reload, memory growth that degrades rendering, or accumulated state that requires clearing. +
_Supports:_ xref:L2-system-design-concept.adoc#SQR-02[SQR-02 The installation recovers without a person present]

=== [[QR-04]]QR-04 Backend interruption is invisible on the surface _(Availability)_

_Applies to:_ <<TF-01,TF-01 Retrieve display material>> +
_Acceptance criteria:_ A failed retrieval leaves the surface unchanged and produces no visible error. Recovery requires no reload. +
_Supports:_ xref:L2-system-design-concept.adoc#SQR-02[SQR-02 The installation recovers without a person present], xref:L2-system-design-concept.adoc#SQR-07[SQR-07 The installation degrades visibly rather than silently] +
_Rationale:_ This deliberately departs from xref:L2-system-design-concept.adoc#SQR-07[SQR-07 The installation degrades visibly rather than silently]'s general rule that failures should be visible. xref:L2-system-design-concept.adoc#SQR-07[SQR-07 The installation degrades visibly rather than silently] protects the participant, who needs to know why nothing is happening. An observer needs no such signal, and an error message projected on a gallery wall is a worse outcome than briefly stale content.

=== [[QR-05]]QR-05 Visitor content cannot alter the surface _(Security)_

_Applies to:_ <<TF-04,TF-04 Render the surface>> +
_Acceptance criteria:_ All content from xref:L2-system-design-concept.adoc#SE-03[SE-03 Backend service] is inserted as text. No path renders it as markup. +
_Element specific:_ Yes +
_Rationale:_ This surface is public and unattended, so the consequence of an injection is a projected wall rather than one person's phone.

=== [[QR-06]]QR-06 Fixed viewport, no scroll, no overflow _(Compatibility)_

_Applies to:_ <<UI-01,UI-01 Projection surface>>, <<TF-03,TF-03 Fit an item to the available space>> +
_Acceptance criteria:_ Content never extends beyond the projected area at the target resolution. No scrollbar appears under any content length. +
_Element specific:_ Yes

=== [[QR-07]]QR-07 Diagnostic tag is available to an operator, hidden by default _(Maintainability)_

_Applies to:_ <<UI-01,UI-01 Projection surface>> +
_Acceptance criteria:_ An address flag appends a session id / origin tag to each item. Absent by default; no visitor-facing affordance exposes or hints at it. +
_Element specific:_ Yes +
_Rationale:_ Same operator need as xref:L2-system-design-concept.adoc#SE-01[SE-01 Input client] xref:L3-SE-01-input-client.adoc#QR-06[QR-06 Diagnostic detail is available to an operator] — see there.

=== [[QR-08]]QR-08 Entry and update motion respect a reduced-motion preference, and are switchable together _(Usability/Accessibility)_

_Applies to:_ <<UI-01,UI-01 Projection surface>>, <<TF-04,TF-04 Render the surface>> +
_Acceptance criteria:_ Both the entry transition and the update pulse are suppressed when the OS-level reduced-motion preference is set, and both are turned off together by a single configuration switch, independent of every other element, with no code change. === [[C-03]]C-03 Fixed target resolution, one of a set of named display profiles _(Technical)_

_Source:_ xref:L2-system-design-concept.adoc#SC-03[SC-03 Build effort is capped and the piece is expendable]. +
_Applies to:_ <<UI-01,UI-01 Projection surface>>. +
_Acceptance criteria:_ The element renders against one of a small set of named _display profiles_, each targeting a single fixed resolution with no responsive behaviour within it. The active profile is chosen at run time by an address parameter (`?d=<name>`), defaulting to the exhibition profile when the parameter is absent or unrecognised. A profile fixes three things: the resolution it targets, the masonry column count (`DISPLAY_COLUMNS`), and the number of items the element requests from xref:L2-system-design-concept.adoc#SE-03[SE-03 Backend service] (see <<TO-01,TO-01 Retrieve display material>>). The profiles defined so far:

[options="header"]
|===
| Profile | Screen | Resolution | Columns | Items
| `dev` | Development on a desktop monitor, landscape | comfortable landscape (~1920×1080) | 2 | 4
| `venue` (default) | The exhibition screen — an LG monitor mounted portrait (rotated 90°); the OS presents it already rotated, so the surface needs no rotation of its own | 1296×2304 | 2 | 12
| `stadium` | A beamer — never used; `venue` ran the exhibition instead (on-site connectivity issues took the projector out of use entirely). Resolution and column count stay unsettled placeholders. | _(unsettled placeholder)_ | 2 | 16
|===

_Consequence:_ Rules out responsive layout work — each profile is still a single fixed viewport under the no-responsive-behaviour rule; the profile set just replaces the earlier assumption of exactly one. `stadium` was never run and stays a placeholder deliberately — not worth settling a resolution for a beamer that may never be used again; resolve it against the real hardware if and when a future exhibition actually uses one, same as `venue` was. Per-profile visual tuning (font size, spacing on the portrait `venue` surface) is done against the real screen, keyed off a profile marker on the surface. +
_Implements:_ xref:L2-system-design-concept.adoc#SC-03[SC-03 Build effort is capped and the piece is expendable]
