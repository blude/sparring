1. What Sparring is

Sparring is an exhibition object built for a master’s thesis at FH Dortmund. A QR code on the wall opens a plain text field on the visitor’s phone. Whatever they type goes to an AI that argues back instead of answering, and both sides of the exchange show up on a wall behind them, so a room full of people watches one visitor get pushed to reason through their own argument. It runs for three days at Superraum in Dortmund. The subject is Digital Design education, and the AI plays a motivated sparring partner rather than a helpful chatbot.

These documents are the design record. They describe what has to be true about the installation and why, not how the code is written.

2. How to read this

The documentation follows a four-level framework. Each level answers a narrower question than the one above it, and every item carries an ID (BG-01, SE-03, TF-02) so a decision at one level traces back to the need it satisfies one level up.

L1: Solution

Why build it. Business goals, the value it creates, the processes around it. Non-technical.

L2: System

The installation as one system. System goals, architecture, the elements it breaks into, and scenarios that run end to end.

L3: Element

One document per element. The behaviour, interfaces, and constraints of each piece L2 named.

LX: Realization

The deployment reality: server sizing, PHP version, SSL, and diagrams at implementation detail. It sits outside the four levels.

There is no L0. The framework defines a Digital Design Brief above L1, but none was produced for this project, so the record starts at L1 and its constraints trace to nothing above them.

3. The four levels

  • L1: Solution Design Concept holds the future press release, the business goals, and the value proposition behind arguing with an AI in public. Start here.

  • L2: System Design Concept covers the system goals, the architecture diagram, the split into three software elements plus one system prompt, and the scenarios that run across them.

  • L3: Input Client (SE-01) is the visitor’s phone screen: consent, the chat UI, alias and avatar, and how a turn is submitted.

  • L3: Display Client (SE-02) is the projected wall: how recent exchanges are polled and laid out so they stay legible across the room.

  • L3: Backend Service (SE-03) is the one stateful service: the turn pipeline (gate, moderate, generate, persist), rate limiting, session policy, and the single outbound call to the language API.

  • L3: System Prompt (SE-04) is the instruction set behind every Sparring reply. It has no runtime interface of its own but is modeled as a first-class element anyway.

4. Beyond the four levels

  • LX: System Realization Concept collects the deployment and infrastructure detail, plus implementation-level diagrams: what talks to what, what each element is built from, and what shapes a response the visitor reads.

  • Glossary lists what every ID prefix means, level by level.
