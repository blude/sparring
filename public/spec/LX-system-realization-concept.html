Reading it: two thin clients (SE-01/SE-02) hold no logic beyond presentation — every rule (moderation, rate limits, session policy, the API credential) lives in SE-03, and SE-03’s only outbound dependency is `PE-01. data/store.db is a single SQLite file inside the backend process, not a separate service; prompts/sparring.md (SE-04) is supplied as content on the outbound call, not a component with its own network edge. No websocket/SSE connection — the wall polls /api/recent-exchanges on an interval instead.
